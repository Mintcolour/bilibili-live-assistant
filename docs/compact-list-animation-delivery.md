# 紧凑列表出入动画

## 使用

入口：“可视化设置 → 紧凑面板 / OBS / 金额停留 → 列表动画”。

- 默认开启，过渡默认 200 毫秒，可调 100–500 毫秒，桌面和 OBS 共用。新消息底部滑入淡入，已有消息平滑上移，顶部消息滑出淡出。
- 混合列表内所有类型统一动画；列表外固定 SC、礼物、上舰、进房、关注和榜单保持原展示、停留及队列规则。
- 设置页提供“播放出入示例”；修改即时预览、保存后应用，支持原有还原修改和草稿保留。关闭动画恢复直接更新。
- 桌面交互浮窗“样式”中也可调整动画并播放示例。播放只向本地调整示例添加一条，不进入真实列表、历史或 OBS。

高峰沿用约 100 毫秒批量发布，直接从当前可见位置衔接最新布局，不建立动画播放队列、不延迟底层消息。一次入场的淡入截止时间不会因后续批次反复延长。头像／表情加载、礼物合并更新同一消息，不重复入场。固定提示展开／收起时，列表衔接布局变化。

首次打开已有列表、恢复窗口、切换模式、保存样式、OBS 刷新或重连直接恢复当前内容。桌面翻阅旧消息时暂停跟随和过渡；回到最新直接定位，不补播积压动画。桌面阅读不影响 OBS。

## 资源策略

桌面复用已有 OverlayFrameClock，沿用帧率设置并参考紧凑窗口所在显示器；仅过渡期间订阅帧回调。逐帧复用消息位图，只计算位置、透明度及绘制，不逐帧解码或上传图片。离场行取消图片等待，最多暂存 4 条、共 4 MiB 原位图，超限或到期释放。隐藏、换房及退出停止并清理。原消息数据和可见行容量保持不变。

OBS 使用 Web Animations 的 transform／opacity，无新增 JavaScript 逐帧轮询。只动画当前可见及正在离开的内容；离场最多 4 个节点，按 CSS 像素面积 × 4 估算上限 4 MiB。该值不代表浏览器实际原生内存。结束后取消动画效果，释放离场节点和图片观察；隐藏、重连、改尺寸、换房清理过渡。

设置预览只播放有限过渡：背景与行图片一次上传，再用 WinUI 变换及透明度动画显示。离开页面停止、解除绑定、释放显示源。预览不请求网络，不建立持续动画计时器。

紧凑窗口诊断增加 animationActive、leavingRows。动画会增加过渡期间的绘制工作，尚无实际 CPU／内存测量，不声称达到 160 MiB 目标。

## 用户手动验收

1. 桌面／OBS 中普通弹幕及列表内 SC、礼物／上舰的入场、上移和离场；固定区停留规则不变。
2. 默认 200 毫秒、100／500 毫秒端点、关闭动画、草稿、保存、还原；两处本地示例不进入真实列表、OBS 或历史。
3. 高频多批消息及时衔接最新位置，淡入不无限延长，离场不残留；头像表情迟到和礼物合并不重复入场。
4. 固定区展开／收起、长消息、窄窗口、拖动缩放及 100%／150%／200% DPI，不重叠或残影。
5. 翻阅、回到最新、切换模式、反复隐藏恢复、换房、退出；OBS 刷新、重连、切换场景不回放旧消息。
6. 无新消息且过渡结束后，animationActive 为 false、leavingRows 为 0；隐藏与关闭预览后资源释放。应用及 OBS 浏览器占用分别观察。

编译通过不代表实际动画流畅度、DPI 效果或性能已经验收。
