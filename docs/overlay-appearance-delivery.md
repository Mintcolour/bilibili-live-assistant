# 浮窗外观、展示节奏与人数同步

分支 `overlay-appearance`，基线 `audience-overlay` 的 `1ea3e0a`。独立发布到 `artifacts/releases/overlay-appearance-v2`，继承 `audience-overlay/settings.json`，不修改用户实际数据库。

## 修改内容

- 去掉固定内容缓存中的重复矩形铺底，统一单次圆角背景绘制。背景颜色和不透明度可调，0 为完全透明。升级后榜单和滚动内容默认透明，礼物等已有卡片背景继续保留并可调整。
- 文字增加默认开启的阴影，可调开关、强度、范围、偏移和颜色；沿用描边。阴影与文字一起缓存到消息位图，不增加逐帧模糊处理。
- 每个区域的“外观 / 类型”菜单增加直接调整面板：每条内容缩放 50–200%、字号、整体不透明度、表情大小、卡片高度、背景和阴影。缩放在光栅化前计算字号与几何，轨道和槽位按实际大小分配。
- 调整面板使用草稿，变化合并为一次延迟 100 ms 的预览；保存才写配置，取消或关闭恢复原设置，不持续轮询。
- 定时卡片可调停留时间，上舰单独设置；已显示卡片按首次显示时间重新计算到期点。滚动模式按固定速度运行，时长由内容宽度和区域宽度决定。榜单滚动使用独立播报间隔。
- 新内容显示间隔可设 0–30 秒：滚动普通弹幕／礼物／SC 限制新消息起播间距，SC 后续分段不插入额外等待；定时卡片限制补入新卡片的间距；固定列表／网格／面板限制批次显示更新节奏。0 保留原有节奏，等待仍受既有数量和时效上限控制。进房沿用立即替换最新三条与独立停留时间。
- 后台榜单采集改用接口解析后的真实房间号，与面板参数统一；首页到达就发布人数和前十名，不再等待后续分页全部完成。后续成员分页失败只标记历史采集不完整，不冻结最新人数。面板已取得的高能榜首页资料同步到人数摘要、曲线及浮窗，旧采样不覆盖新采样。列表统计取首页总人数，显示实际采样时间，不增加额外请求、不改写旧历史。

## 静态验证与手动验收

只进行静态检查、Release x64 编译、独立发布和产物核对；不启动程序、不运行自动测试、不访问用户实际历史库。核对 ReadyToRun、BrowserHost、SQLite 8.0.32、AMD64、PerMonitorV2、设置继承和 ZIP 内容 SHA256。验证结果保存在 `artifacts/overlay-appearance-v2-verification/release-verification.json`。

由用户手动验证：

1. 用短房间号和真实房间号连接同一主播，对照榜单首页总人数、头像统计、曲线和浮窗；同时刷新和切换房间时，旧请求不覆盖新状态。
2. 榜单透明底；礼物背景降至 0 后没有矩形底和边框，改色、背景强度与整体透明度符合预期。
3. 各区打开“外观 / 类型 → 大小、透明度、背景与时间”，调节内容缩放、字号、表情、阴影；预览清晰，无重叠，保存和取消正确，重启后设置保留。
4. 对照普通礼物、上舰、SC、进房的停留时间；调整显示间隔，检查空闲时不轮询，满队列、省略与长 SC 连续分段符合规则。
5. 窄区域、大字号、高 DPI、媒体和大表情、切换模式、隐藏、换房和退出时检查资源释放。缩放或字体改变后，已有滚动媒体可退回原文以重新匹配轨道，后续新消息继续按媒体规则显示。
6. 长时间和高流量下手动观察 CPU、内存。编译与文件核对不代表运行效果或性能已经验证。
