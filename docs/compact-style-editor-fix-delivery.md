# 紧凑浮窗样式按钮修复

发布目录：`artifacts/releases/compact-style-editor-fix`。继承 `archive-resource-efficiency` 当前设置，旧发布目录保留。

## 原因与修复

紧凑浮窗顶部「样式」和右键「调整样式」共用 `CompactQuickEditor`。其中数字控件原来先写 `Value`，再设置 `Minimum` 和 `Maximum`。WinForms 数字控件的初始上限为 100，默认动画时长为 200 毫秒，在构造窗口时就会触发数值越界；表情尺寸超过 100 也会出现同类问题。未找到可用于核对此次点击堆栈的 `runtime-errors.log`，此结论来自控件初始化顺序及默认值的静态检查。

- 先配置数字范围，再填入经约束的值；保留动画时长 100–500 毫秒、表情大小 16–128 及其他原有范围。
- 打开时规范化草稿，阻止重复打开；打开失败记录 `compact-style-open` 并恢复预览／阅读状态。窗口销毁后忽略预览回调。
- 保存时冻结草稿并禁止重复操作；保存完成前禁止普通关闭，成功后恢复关闭。失败记录 `compact-style-save`，恢复编辑。错误日志沿用只记录类型、HRESULT 和代码堆栈的规则，不写用户消息或账号资料。
- 保留关闭不保存时恢复原样式、保存后应用，以及已有位置和尺寸。未改变 OBS 输出、队列顺序、显示时间、内存预算或历史记录。

## 验证与使用

开发侧仅静态检查、Release x64 编译和发布核对，不启动 App、BrowserHost、浏览器或 OBS，不运行自动测试。编译成功不代表按钮实际点击已经验证。

关闭旧软件后使用新目录的程序。请手动检查：

1. 紧凑模式 → 开启互动浮窗 → 点击顶部「样式」，以及右键「调整样式」，均能正常打开。
2. 动画时长 100／200／500 毫秒、表情大小 100／128 时关闭后重开，无越界错误。
3. 修改字号、透明度、显隐、演示动画；关闭不保存恢复原样式，保存后重开保留修改。
4. 反复打开／关闭，保存时连续点击或尝试关闭；再检查顶部「最新」「完成」、拖动缩放、隐藏恢复及阅读模式。
