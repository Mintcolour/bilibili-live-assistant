# 弹幕、礼物与上舰头像修正

## 原因与修正范围

- `SEND_GIFT_V2` 的 protobuf 已提供头像、舰队身份和粉丝牌，但原模型只读取 UID、名称和礼物列表，界面收到的事件没有外观资料。现按 blivedm 的字段定义补齐，并传递礼物图片和上游时间。
- 普通弹幕原来仅读取当前消息的头像地址，缺少头像字段时没有补全路径。现兼容 `user`、`uinfo`、`sender_uinfo` 和直接头像字段；上舰等消息也逐字段回退，避免空的 `uinfo` 遮住实际发送者头像。
- 为仍缺少头像地址的可见消息加入 UID 补全。只有正值 UID 能发起查询，不使用昵称猜测身份；匿名、测试及示例消息不会触发用户资料查询。

本次没有采集真实弹幕网络包，不能据此断言截图中的每条消息都缺少同一个字段。修正覆盖已确认的礼物字段遗漏，以及普通弹幕和上舰缺少头像时的显示路径。共享显示源上传和绑定未发现新的异常日志；保留上次 `SoftwareBitmap` 生命周期修复。

## 补全与资源边界

- 先采用消息自带头像，并共享实际收到的同 UID 头像；只在可见内容仍缺少头像时访问固定公开接口 `https://api.bilibili.com/x/web-interface/card`。校验返回 UID 相符后，只接受 B站图片 CDN 地址。
- 请求不携带 Cookie、不接受重定向，不保存个人资料响应。头像图片继续复用原图片下载、像素、显示源租约和磁盘缓存。
- 同 UID 共享请求，最多 2 个工作并发、16 个进行中键；新请求启动间隔至少 1 秒。容量不足时可取消地等待，不新增逐消息后台任务队列。
- 资料响应最多 1 MiB；发起 HTTP 后，响应头和正文合计最多等待 8 秒。缓存最多 512 个 UID，成功保留 10 分钟，失败冷却 5 分钟；限流或风控响应另暂停新查询 1 分钟。
- 离屏、回收或窗口隐藏时取消该消费者；最后一个消费者离开后取消共享查询。换房清空资料缓存并取消旧代次，退出时关闭服务。不增加常驻轮询计时器。
- 文本和已有表情先显示，头像请求独立进行。滚动弹幕、滚动礼物／上舰及固定卡片均只更新当前显示实例，不重新播报；固定卡片保留原消息引用用于复用判断，头像补全不会导致每批消息重建卡片。
- 无有效 UID、接口拒绝或头像图片不可用时保留默认图标，不阻塞监视或增加重试频率。首次头像出现时间依赖网络和队列，不能保证立即显示。

性能诊断 schema 继续为 3，新增 `avatars` 数量统计，以及 `imageResources.avatarBindings`、`missingAvatars` 累计计数。它们只记录数量，不包含 UID、昵称、消息、URL 或账号资料；原分析脚本继续可读。

## 编译与交付核对

- 静态核对普通弹幕／礼物／上舰解析、UID 校验、请求共享、取消、代次、固定卡片复用和资源关闭路径。
- Release x64 编译；发布目录 `artifacts/releases/memory-image-pipeline-avatar-fix`。
- 继承 `memory-image-pipeline-fix/settings.json`，核对字节一致，不解析或输出配置内容。
- 核对 ReadyToRun、AMD64、PerMonitorV2、SQLite 8.0.32、BrowserHost、图标、诊断分析工具及分享包内容。
- 按约定不启动应用、BrowserHost，不运行自动测试或读取真实历史库。编译及文件核对不代表已验证头像实际显示或运行资源占用。

## 手动验收

1. 查看真实普通弹幕、礼物、上舰，检查头像、粉丝牌和身份；同一用户多条消息应复用头像。
2. 在概览列表、卡片和各种浮窗中检查，头像稍晚到达时原消息保持位置与展示期限；已有表情不等待资料查询。
3. 滚动离屏再返回，隐藏／恢复窗口，资料请求期间换房或退出，不出现旧头像回填或退出异常。
4. 匿名无 UID、接口失败或限流时允许默认头像；监视与文字显示应继续，诊断中的请求并发、缓存和失败数保持受限。
5. 如继续排查，可开启原性能诊断，对照新增头像计数和图片错误阶段。未实测的 CPU、内存及网络表现仍需通过实际运行记录判断。
