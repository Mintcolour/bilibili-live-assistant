# 1820703922 概览内存续查

本轮采用用户最新指定的房间 1820703922。目标仍是解决持续异常增长，尚无完成或长期稳定结论。正式程序、正式设置、账号库和历史库未修改；真实房间只通过隔离 StressApp 观察，账号在内存中读取，历史与图片目录独立。

## 构建来源纠正

前两轮 `room22748536-current-v40` 与 `room1820703922-current-v41` 从压力项目默认 bin 目录启动，没有 `soak-build.json`，不能证明它们对应当前工作区源码。运行中的计数也出现 `movedCards=0`，而重新编译当前源码后，同类流量的 `movedCards` 已正常增加。因此这些日志只能作为其实际二进制的观测，不能用来推断当前 `PreserveMessageCards` 实现的效果。

v40、v41 均已按精确可执行文件路径结束，记录 `observation-ended.json`；不作为正常退出或归档排空证明。两者曾短暂重叠，不用任意峰值差解释优化效果。

后续真实房间启动要求存在构建清单，并核对 StressApp.dll 和清单中的 WinUI 原生模块 SHA256。新构建记录应用、Core、Infrastructure 与隔离 harness 的源码指纹，编译前后不一致时拒绝标记为可追溯构建。清单仅描述构建输入，不代表性能通过。新增 `transportShape` 只记录消息类型、头像、徽章及表情的聚合数量，不记录正文、URL、昵称、UID 或凭据，也不保留消息对象；资料服务事件不计入这组传输统计。

## 已完成短观察：v42

`room1820703922-verified-v42` 从当前源码重新编译的 `build-dashboard-verified-v42` 启动，原 SDK、完整图文功能、概览和紧凑浮窗，采用默认显示设置。约五分钟流量采样，所有样本均为概览与紧凑浮窗可见，连接样本占比 100%，共收到 1,127 条事件，正常退出。

私有工作集峰值 131.86 MiB。排除最初一分钟后的约 3.85 分钟中，工作集约 110.12 → 128.85 MiB，回归斜率 +4.6874 MiB/分钟；提交量约 184.77 → 203.35 MiB，斜率 +4.6699 MiB/分钟。像素缓存仍在增长，短观察未覆盖稳定预热，不向一小时或长期外推。

停止监视、保留窗口约 30 秒后，工作集约 129.94 MiB、提交量约 204.46 MiB。随后隐藏约 30 秒，末值约 125.84/201.52 MiB；图片显示源、租约、闲置源、待上传、待图片请求、显示队列和归档待写归零。像素缓存仍约 10.97 MiB。图片释放账目归零和进程未回到启动值同时成立，尚不能据此归因于某个原生对象或认定永久泄漏。

该轮未读取 UIA、截图、dump 或原生堆；没有强制 GC、裁剪工作集或手动释放 WinRT COM。完整数字结果保存在忽略目录中的 `analysis.json`。

## 对照与后续

v43 使用隔离源码副本，仅暂停 DashboardUi 描述/Tooltip 更新和消息卡片语义描述更新，其余显示保留。该实验会减少辅助功能信息，不进入生产代码或交付包。约五分钟流量观察正常结束，共收到 757 条事件；峰值工作集 122.39 MiB。排除最初一分钟后，工作集斜率 +2.2337 MiB/分钟、提交量斜率 +5.9495 MiB/分钟，平均收到 2.41 条/秒；基线对应 3.57 条/秒。末尾隐藏后显示源和租约归零，最终提交量仍约 209.63 MiB。真实流量和图片缓存压力等级不同，不把工作集峰值差解释成改善；该实验没有解决增长或高位保留，没有删减生产提示或无障碍功能。

v44 构建仅增加聚合诊断，不改变生产 UI。更贴近日常使用的观察须继承 `live-settings-preview/settings.json` 的外观设置，包括概览 250 ms 刷新和展开的榜单；默认外观短观察不能替代此场景。

原生堆追踪另用独立诊断进程，只录制短时间、限定 PID 的分配/释放，避免此前全量启动追踪撑满文件。追踪前写入干扰标记，之后的数据不作为正常稳定性验收。ETL 与内存数据仅留本机忽略目录，不进入分享包。

### v45 短堆采集

`room1820703922-native-window-v45` 使用 v44 完整功能构建、原 SDK、发布版外观，正常退出。独立提权助手核实管理员 token 与目标进程绝对路径后，仅对 PID 18748 启动 `BiliNativeShort-v45` heap logger，未更改注册表或其他追踪会话。约 8.8586 秒后成功停止，ETL 为 77,987,840 字节；xperf 报告丢失缓冲和丢失事件均为零，TraceEvent 读取约 343,881 条事件。追踪前的干扰标记已写入目标日志目录。

从微软符号服务器仅补充当前二进制匹配的 DWrite、GDI+、RTMediaFrame 和 dwmcorei 符号，解析结果保存在本机。可见栈包含 `DWriteTextAnalyzer::GetGlyphs` / `CTextBlock::MeasureOverride`、`SoftwareBitmapImpl::CopyFromBuffer`、`GpGraphics::DrawImage` 与合成资源创建。它们只是分配路径，尚无永久保留或根因证明。

逐事件核对后，旧 reader 的 3,672 个地址覆盖全部对应同线程、同尺寸、间隔不足 1 毫秒的内层 Alloc(new) 与外层 ReAlloc(old,new)，旧地址已被内层 Free 释放。修正配对后，没有不明地址替换，未配对释放为 9,036，另有 2 次旧重分配地址不可见；不能把嵌套事件重复计作分配量。可复现的离线工具保存在 `tools/NativeHeapReader`，不进入正式程序依赖。

末尾可见存活 8,859 项、2,534,649 字节，其中持有至少 5 秒的为 872 项、144,672 字节。配对释放的年龄桶（0–1／1–10／10–100／100–1000／1000–5000／超过5000毫秒）分别为 73,487／5,988／2,573／5,975／13,751／39 项。此证据说明存在大量短期周转，不能证明长期收敛；附加前的分配不可见，末尾存活也可能是正常缓存，不能称为精确泄漏量。
