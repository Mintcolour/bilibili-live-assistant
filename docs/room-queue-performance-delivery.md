# 22748536 浮窗顺序与绘制开销修复

## 原因与行为

用户确认顺序异常主要出现在浮窗。定时卡片原先按固定数组槽位显示，最早卡片到期后，新卡片回填顶部槽位，可能排到尚未到期的旧卡片前面。本版按首次实际展示的顺序排列，旧卡片向上补位，新卡片在下方出现；旧位图、图片请求及到期时间保留。普通弹幕固定网格的槽位规则不变。

滚动礼物原先从最后一条就绪消息开始取，造成后来先播；上舰也会进入礼物合并等待，并与普通礼物共享拥堵上限。本版改为上舰优先使用下一个空位，同类最早就绪先播。仅普通礼物按既有窗口合并，上舰不合并、不等待礼物合并窗口。礼物／上舰待播各最多64条，礼物等待60秒、上舰与SC等待300秒；礼物满时保留较新提示，上舰和SC满时保护已经入队的消息。过时或超限仍可能省略浮窗提示，概览及原始历史规则不变。

SC继续按收到顺序播报，长SC各段连续展示；定时卡片上舰优先下一空位，不打断已经显示的卡片。跨类别优先级、普通礼物合并等待以及配置的展示间隔，仍可能导致礼物与上舰不按全局接收时间交错播放。概览中用户选择的时间／金额／数量排序不被重置。

实测发现主要CPU开销在普通滚动弹幕逐帧绘制，礼物及SC固定卡片重绘占比较小。本版把分离轨道的复杂GDI+裁剪改为逐个矩形裁剪，同时只提交当前轨道实际需要的源图像素，保留采样边缘余量、双线性插值、1:1亚像素移动、阴影、字号、透明度和目标帧率。待播消息不改变当前画面时，不再重复提交固定卡片窗口。

新增overlayRaster与overlayPresent计时，分别观察栅格绘制和窗口提交；保留原计时字段。固定窗口增加处理、重建、位图更新与重建触发提交次数；提交次数不包括异步图片补齐触发的重画。计数不含消息内容、UID、URL或账号。没有新增设置或修改数据库结构。

## 隔离核对

Release x64压力程序集运行22项针对性检查：SC与礼物到期补位顺序、位图复用、到期时间不重置、单纯入队不重画、上舰优先与不合并、各类容量和等待期限、同类FIFO，以及5组负数／分数坐标下的裁剪像素差异。源图裁剪改变GDI+变换的舍入，像素检查允许每通道最多2/255的差异，不能宣称最终版逐字节完全相同。

固定绘制场景交替运行6组新旧批次，每批40帧，不能代替真实直播CPU结论。另一次保留全帧源图采样范围的对照虽逐字节一致，但直播复核未体现CPU收益，没有选用该版本。最终版采用当前轨道源图裁剪，边缘差异及实测结果分别记录。

诊断程序使用匿名连接、独立历史和图片目录，不读取用户Cookie、设置或真实历史。仅本轮明确授权的直播实测及故障针对性诊断被运行；未启动正式应用、BrowserHost或无关自动测试。

## 直播实测

房间22748536，概览与浮窗持续显示，头像开启、表情动画关闭，125% DPI，滚动区域2560px宽，目标60 FPS，20逻辑处理器。基线监视240秒，全帧源图对照240秒，最终版收尾120秒；均另有启动等待5秒、预热10秒。日志约5秒采样，另用250ms外部进程采样。截图诊断会额外分配内存，这些短测不能作为长期资源验收。

CPU为进程CPU按20逻辑处理器归一。绘制耗时是UI日志区间内的普通弹幕绘制总耗时／次数；交付版本约59.55次绘制回调／秒，不等于测得屏幕实际呈现帧率。各次直播消息、文本长度、不同头像及图片下载量均不同，不能将P95的小幅下降解读为稳定降幅，中位数及每次绘制耗时也没有呈现一致改善。此次确认的是队列顺序修复、重复固定卡片提交减少、固定合成场景小幅收益；尚未证明真实直播总体CPU显著降低。早期候选曾观察到P95约3.17%，也没有在收尾复核中稳定复现。

最终版固定合成场景新旧各240帧，总耗时950.89／916.54 ms，约下降3.6%；5组像素比较最大通道差异依次为2、0、2、2、0。此结果仅适用于该小型合成场景。

交付版250ms采样494次，观测峰值152.08 MiB，本次没有超过160 MiB；早期候选峰值175.80 MiB，基线和全帧对照也超限，短测没有通过长期160 MiB验收。基线外部采样约从程序第32.83秒开始，未覆盖启动后全部阶段；交付版采样从约第5.36秒开始。有限采样不能排除采样间峰值。

三次均生成completed.json、概览及浮窗持续可见，没有归档队列遗漏或写入失败。资源分析脚本对短收尾运行标记incomplete：这不是长期显示、保留内容和资源预算验收通过。没有运行小时级测试，不以编译或短测代替160 MiB长期验收。

请重点观察连续SC、礼物和上舰：卡片从上到下保持实际展示先后，新卡片补在下方；每张卡片仍按自身配置到期。切到滚动模式后，同类按就绪先后播报，上舰在下一空位优先。长SC不得被另一条SC插段。继续检查窄区域、透明边缘、阴影、换房和隐藏恢复。
