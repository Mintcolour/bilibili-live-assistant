# 概览内存优化手动试用版

日期：2026-10-19。分支：`dashboard-card-rebind`。本包供用户手动测试当前修改，不代表内存泄漏已经全部解决。

## 包含的修改

- 概览按消息身份保留并移动现有行，减少新消息到来时反复改写整列富文本；普通文字、大表情及带特效进房行复用有上限的控件结构。
- 回收行立即解除图片和操作绑定，避免先清空再填写文本；清空、换房及更换样式时释放旧控件，延迟回收事件不能重新填充已清理的池。
- 仅为可见行加载图片。头像、表情、头像框及媒体仍沿用原像素管线、尺寸与清晰度；共享显示源和像素缓存保留数量、字节及资源压力预算。
- 消息保留辅助功能语义、选文、已读、感谢与媒体操作。字体、阴影、透明度、动画、帧率、消息容量、历史及登录规则不变。
- 保留资源调试日志与分析工具；不通过强制 GC、工作集裁剪或手动释放 WinRT COM 压低数值。

隔离诊断中的替代 WIC 解码器、关闭文字选择、暂停描述通知、扩大缓存项数，以及加速历史回放均未启用在正式程序中。回放与原生堆诊断工具不放入分享包。

## 已有观察与限制

房间 1820703922 的当前源码隔离观察已正常完成约一小时，9,486 条事件，采样中概览与紧凑浮窗同时可见。私有工作集峰值 145.99 MiB；最后三十分钟均值 136.10 MiB，工作集／提交量回归斜率分别为 -0.1468／-0.0973 MiB/分钟，归档无报告遗漏或故障。这支持该负载后段收敛，不能推广到所有直播间。

三十分钟真实记录本机回放也已结束，工作集峰值 145.88 MiB，但排除前五分钟后的工作集／提交量斜率仍为 +0.3230／+1.1067 MiB/分钟；较短固定输入的回放亦有缓慢正斜率。十倍加速的二十分钟回放正常结束，平均约 24 条/秒，收到 28,858 条事件，工作集峰值 148.51 MiB，排除前五分钟后工作集／提交量斜率为 -0.0083／-0.0201 MiB/分钟，停止隐藏末端图片源、租约及待处理计数归零，归档无遗漏或故障。它重复固定记录并有 49 次图片缺失请求，不能替代持续出现新用户、新图片的长直播；旧四个 UI 文件的同输入诊断也未重现 600 MiB。因此不能认定所有负载已经稳定，也没有确认旧版约 600 MiB 的完整根因。

停止监视后保留可读消息会继续持有其显示资源；隐藏全部页面后可见图片租约和显示源应释放。进程不立即回到启动占用既可能涉及仍可读内容和有界缓存，也可能涉及框架／分配器保留，需结合后续走势检查。

## 手动使用

1. 先关闭旧版，再从新目录启动 `BilibiliLiveAssistant.App.exe`，不要只复制单个 EXE。
2. 本机发布目录继承 `live-settings-preview/settings.json`，保留现有外观和历史目录配置；原发布目录不覆盖，历史数据库不复制、不清理。
3. 开启性能调试采样，按日常方式使用概览与浮窗，重点观察预热后是否持续增长。记录房间、显示模式、切页／换房和停止时间，便于对照日志。
4. 检查头像、透明表情、大表情、进房特效、SC／礼物、阅读与感谢、滚动离屏、模式切换、隐藏恢复和换房，确认没有空行、图片消失或旧消息串入。

分享 ZIP 排除用户设置、OBS 密钥、凭据、历史库、图片缓存、日志、dump 和 PDB。解压分享包时需自行沿用设置；本机目录已经继承设置。
