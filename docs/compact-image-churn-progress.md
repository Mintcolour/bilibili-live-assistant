# 紧凑浮窗图片周转续查

日期：2026-10-19。分支 `dashboard-card-rebind`，代码提交 `62c3de2`。这是一处减少重复图片工作的小范围修复，不代表已找到此前所有高位内存的来源。

## 当前修改

紧凑行首次绘制会同步读取已缓存的头像、表情和装饰，原先随后仍对这些图片逐项请求，并在请求结束后重建整条位图；失败结果也会触发重建。现在由渲染器回报本次成功读取的图片标识，已经绘入当前位图的图片跳过后续请求；只有未绘入且加载成功的图片需要补画。

判断依据是该行实际绘制时的结果，避免把“异步加载开始时已在缓存”误认为“首次位图已经包含”。首次绘制后才填入缓存的图片、延迟取得的头像仍会补画。行只保留 URL 标识，不常驻保留像素资产；回收、换房和隐藏仍沿用现有取消与当前行校验。字体、图片清晰度、阴影、透明度、动画、帧率、队列、OBS 和历史规则不变。

紧凑浮窗诊断新增四项进程累计计数：`bitmapCreates`、`imageRefreshes`、`paintedImageSkips`、`failedImageLoads`。仅记录数量，不记录图片地址；旧日志仍可读取。
