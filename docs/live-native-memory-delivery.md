# 真实直播内存稳定性候选版

当前分支为 `live-native-memory`。本轮目标是解决预热后异常持续增长，不再把 160 MiB 作为硬门槛。

## 状态

2026-10-18，真实房间 1713546334 的两套一小时概览＋紧凑浮窗观察均已正常结束。**采样覆盖完成，但内存仍缓慢增长，未通过稳定性验收；当前产物仍为候选包。**

| 观察 | 实际流量采样 | 私有工作集峰值 | 后 30 分钟工作集斜率 | 后 30 分钟私有提交量斜率 |
|---|---:|---:|---:|---:|
| v16 原图片管线 | 60.85 分钟 | 178.40 MiB | +0.4895 MiB／分钟 | +0.9309 MiB／分钟 |
| v18 隔离 WIC 对照 | 60.84 分钟 | 175.93 MiB | +0.4608 MiB／分钟 | +0.8424 MiB／分钟 |

两套流量样本均为概览与紧凑浮窗可见，连接样本占比约 98%；可见性保持功能在采样时恢复过窗口，不证明采样之间绝无短暂隐藏。用户已确认两套图文显示正常。三进程并存、启动时间与真实流量差异限制直接比较，不能把峰值差当作修复节省量。WIC 对照与显式关闭图片异步操作的 v17 实验均未进入生产代码；v17 原生堆诊断之后的数据已排除。

停止监视并隐藏约一分钟后，v16／v18 图片源、租约、闲置源与待处理队列归零，归档没有报告丢失或故障，但工作集仍约 171.86／170.54 MiB、提交量约 304.19／311.11 MiB。显示资源账目不能解释全部保留。旧正式程序另一次十分钟外部采样仍高位保持约 626.59 MiB 工作集、697.29 MiB 提交量，没有在这十分钟继续快速上涨，先前增长仍未解决。

此前房间 30858592 的 v12 虽已正常结束，但仅有约 7.35 分钟双窗口覆盖，其后仅浮窗阶段的收敛证据不替代本轮双窗口结果。

用户已同意以管理员身份重新打开 Codex 后继续采集原生分配调用栈。此前 WPR 被 `0x80070005` 拒绝访问；下一轮先核实权限和已有会话，只追踪独立诊断进程。操作边界与证据位置见 `docs/native-memory-admin-handoff.md`。

## 已有修改

- 概览按消息身份保留和移动现有控件，减少重复换绑；普通文字、大表情与带特效进房行使用有上限的复用结构。
- 回收池解除图片及操作绑定，避免先清空再填写富文本；清空、换房和样式变更时回收旧控件，阻止延迟容器事件重新填充已清理的池。
- 消息行提供完整的辅助功能语义及操作入口，避免反复展开内部文本范围。
- 图片缓存仍有数量和字节上限，现有资源压力等级也回收闲置像素；不降低解码质量、字体、阴影、动画上限或帧率。
- 分析工具同时展示分段斜率、谷值、均值、私有提交量和预热后走势。旧阈值结果仅保留兼容，不作为新的稳定性判定。

关闭行内选文、更换 PNG／JPEG 解码器及 SDK 对照只存在于隔离诊断版，没有进入生产代码。本候选保留行内选文及原 SDK、图片格式与功能。

## 验证与边界

隔离观察使用真实账号连接真实直播间、生产概览及紧凑浮窗源码，历史与图片目录独立。账号仅在进程内读取，不复制或修改凭据库，不启用第二个 OBS 服务。正式旧进程及其历史继续保留。

本轮没有强制 GC、工作集裁剪或手动 COM 释放。观察期间不对候选进程读取 UIA 树、截屏、采 dump 或查询原生堆。此前经过堆诊断的样本单独标记，不进入无干扰的验收区间。

私有工作集、私有提交量和总工作集分别报告。单次峰值、短时下降、较小图片预算或一轮编译均不能证明泄漏修复，也不能证明无限期运行稳定。

正式应用及 BrowserHost 只做 Release x64 编译和文件核对；真实启动观察使用隔离程序，没有运行自动回归测试。还需人工验证正式程序的登录工作流、阅读、感谢、媒体、模式切换、隐藏恢复及换房释放。

## 产物

候选发布目录为 `artifacts/releases/native-memory-candidate-v1`，仅本机目录继承 `live-settings-preview/settings.json`。分享包排除用户设置、凭据、数据库、诊断日志、dump 和 PDB。旧发布目录不覆盖。

本轮结尾仅更新分析与说明，没有新的生产性能修复、重新编译或新发布包，不将现有候选作为“增长已修复”版本交付。

排查过程与证据边界见 `docs/live-native-memory-progress.md`。
