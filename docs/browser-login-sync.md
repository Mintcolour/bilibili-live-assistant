# 浏览器登录状态本机同步

实现分支：`browser-login-sync`。本次完成源码、Release 发布和静态核对，真实浏览器流程及性能仍待手动验收。扩展使用开发模式加载，尚未上架 Chrome 或 Edge 商店。

本次最终本机发布目录为 `artifacts/releases/browser-login-sync-v1/`，分发包为 `browser-login-sync-v1-win-x64.zip`，扩展包为 `browser-login-sync-v1-extension.zip`。请使用这一版；较早的 `browser-login-sync` 和 `browser-login-sync-release` 目录是实施中产生的产物，未包含最终权限修正。

## 首次连接

1. 解压完整 Windows x64 发布包，双击 `BilibiliLiveAssistant.App.exe`。
2. 打开“账号设置 → 连接浏览器”，选择 Chrome 或 Edge，点击“安装／修复本机连接组件”。只有点击此按钮才修改当前用户的组件目录和注册项，不需管理员权限。
3. 点击“打开扩展文件夹”。在所选浏览器打开 `chrome://extensions` 或 `edge://extensions`，开启开发者模式，选择“加载已解压的扩展”，选中 `browser-extension` 文件夹。ZIP 须先解压。
4. 核对扩展名“B站直播助手 · 本机登录同步”，开发版固定 ID 为 `lnmblcjfmiaeihkogpmkbjmpngnfkjme`。建议固定到浏览器工具栏。
5. 在该浏览器自行登录 B站。在助手保持连接向导打开，在扩展弹窗为普通配置命名，点击“连接直播助手”。来源请求和向导有效期均为 2 分钟，过期后重新打开向导并发起连接。
6. 助手选择并确认来源。确认前只传来源名称，不传 Cookie。若需要账号读取，明确勾选“确认后切换为账号读取”；当前匿名模式默认保留。
7. 在扩展点击“已在助手确认，完成连接”。助手验证后显示头像、昵称和“已验证登录”。只有“已保存本机状态”时还不能视为登录已验证。
8. 在概览选择房间并自行开启监视。绑定、同步、软件重启均不会自动开启直播监视或悬浮窗口。

普通配置支持 Chrome 120+ 和当前 Edge；不支持无痕、Firefox、多活动来源或跨设备同步。各个浏览器配置都有独立来源 ID；名称由用户命名，软件不读取浏览器磁盘配置目录。

## 同步、身份与退出

- 自动跟随默认开启，由扩展弹窗控制。变更需本机保存与桌面通知确认；通知失败时显示待确认，重试不会被提前显示成已生效。
- 获取浏览器最新登录状态请在扩展点击“立即同步”。助手“在浏览器同步”提供操作指引，“刷新本机状态／重试验证”只读取本机快照并重试身份验证，不能唤醒休眠扩展读取浏览器。
- 同一凭据未变化时跳过写盘、重复身份验证和连接重建；有效期变化但凭据未变化时保留已有验证结果。助手重新启动仍重新验证曾经登录的身份。
- 账号切换会取消旧验证与认证请求，只应用最新快照。监视期间必要重连保留同房间历史和统计；匿名选择始终优先，不向直播请求发送已保存的账号 Cookie。
- 完整快照明确缺少 SESSDATA 或身份接口明确失效时停止使用旧凭据，默认继续匿名读取。账号设置可以改为“停止直播监视”。网络错误、HTTP 403 和异常资料显示暂不可验证，等待用户重试，不当作用户退出。
- 浏览器关闭或后台休眠不会清除本机仍有效的凭据。桌面不持续探测浏览器是否在线，账号页以最近同步时间和组件检测结果为准；扩展显示实际同步失败原因。
- “断开同步”撤销来源及令牌、清除本机登录凭据，不删除浏览器站点 Cookie。更换来源先断开；旧来源后续消息会被拒绝。
- 扩展关闭自动跟随后不再处理自动 Cookie 变化。主动同步失败仍有一项有界重试，关闭后台后由一次性 alarm 补偿，不保活后台。

## 修复、卸载和配置迁移

组件稳定安装在 `%LOCALAPPDATA%/BilibiliLiveAssistant/browser-sync/`，Native Host 名为 `cn.bililiveassistant.browser_sync`，协议版本 `1`。完整独立 .NET 8 x64 运行时随 `BrowserHost` 发布，不依赖开发电脑的运行时。

安装使用唯一临时版本目录，逐文件校验哈希，再切换清单；Chrome／Edge 在 HKCU 的 32 位与 64 位 NativeMessagingHosts 视图分别注册自有名称。已有非本项目注册项、归属不匹配或重定向路径会拒绝修改。软件启动仅检测，不自动安装。组件正忙时请稍后重试。

主程序移到新目录后，浏览器仍指向稳定组件目录；升级版本后点击“修复已绑定浏览器的连接组件”，再在扩展立即同步。修复不撤销当前绑定。注册部分失败后重新点击修复；不会强制结束桥接进程。旧版本目录保留有限数量，并保留 Chrome／Edge 清单仍引用的版本。

“高级设置 → 卸载本机连接组件”只删除自有注册项和归属明确的组件目录，不删除浏览器父级目录。默认清除账号凭据；取消该选项则撤销浏览器绑定、把保留凭据转为手动导入并重新验证。扩展需另到浏览器管理页移除。

账号状态与令牌在 `%LOCALAPPDATA%/BilibiliLiveAssistant/auth/state.dat`，以 Windows DPAPI 当前用户加密，目录权限仅当前用户和 SYSTEM。普通 `settings.json` 不再序列化 Cookie 或令牌，界面也不会回填敏感字段。

首次读取当前发布目录的旧配置时，新加密库为空才迁移原手工凭据；写入及回读成功后原子保存无敏感字段的设置。已有浏览器状态优先。迁移失败保留原配置并阻止后续设置写入，修复后重启重试。只迁移当前目录，不扫描或清除其他版本的旧设置；含旧凭据的旧目录配置仍须自行妥善保管。

密文损坏或来自其他 Windows 用户时，软件不覆盖原文件。可在高级设置明确确认“恢复不可读取的账号存储”：原文件保留为 `state.unreadable.dat`，然后重新绑定。若已经存在该备份，先点击“打开账号存储目录”，自行保留或清理备份后再恢复。此入口拒绝重置可正常读取的库；访问权限问题须先修复权限。迁移失败时恢复后须重启。DPAPI 密文不能作为跨电脑可移植登录配置。

本机发布目录继承上一版 `media-cards/settings.json`（包含此前 DPI、字体、布局、媒体、礼物设置）；可分发 ZIP 不包含这份用户设置、密文或浏览器凭据。

## 资源和传输边界

| 项目 | 实现限制 |
| --- | --- |
| 活动来源／待确认来源 | 1 个／最多 4 个，各 2 分钟 |
| Cookie 范围 | 仅 SESSDATA、bili_jct、buvid3；两个 HTTPS API URL 适用的普通、非分区 Cookie；冲突与权限不足拒绝同步 |
| 本机消息／单个 Cookie | 64 KiB，读取长度后再分配正文／8 KiB |
| 写入锁／通知 | 等待 500 ms／连接 300 ms，总计 1.5 秒 |
| 桥接 | 同一用户单份处理，目标 5 秒；每次 sendNativeMessage 后退出；无 HTTP、TCP、服务或常驻连接 |
| 扩展 | 单份发送与 dirty 状态；2 秒合并、存活时 10 秒目标、5 秒限频；一次性 alarm 最少 30 秒，不保证休眠后秒级同步 |
| 失败重试 | 一项任务，30 秒、2 分钟、10 分钟后停止；用户可手动重试 |
| 身份验证 | 1 个请求，10 秒超时，最多 256 KiB；无空闲验证轮询 |
| 桌面更新 | 一项最新读取／验证；1 秒合并必要连接重建，用户停止优先 |
| 图片／诊断 | 账号头像复用有界图片缓存，隐藏释放；本轮不写额外诊断日志 |

扩展仅持久保存绑定令牌、来源、序号、dirty、指纹和重试元数据，不保存 Cookie 内容，不使用 storage.sync，不注入页面脚本。Native 消息只走本机标准输入／输出，通知管道不携带凭据。当前用户权限与来源校验不能抵御同一 Windows 用户下的恶意进程，不作绝对安全承诺。

站点权限只包含 `bilibili.com`、`live.bilibili.com`、`api.bilibili.com`、`api.live.bilibili.com` 四个确切主机（两个目标主机及其父域），覆盖 HTTP／HTTPS Cookie origin。Chromium 按 Cookie 自身的域及 Secure 标记检查权限：父域 Cookie 需要父域权限，非 Secure Cookie 即使适用于 HTTPS 接口也需要其 HTTP origin 权限。软件查询和访问仍只使用两个 HTTPS 目标，不发起 HTTP 请求，不申请任意子域或其他网站权限。仅给两个 HTTPS API 主机权限会静默漏掉父域及非 Secure Cookie，因而不能采用。依据：[Chromium Cookie 权限筛选实现](https://github.com/chromium/chromium/blob/main/extensions/browser/api/cookies/cookies_helpers.cc)。

## 手动验收

以下尚未在真实浏览器执行；编译通过不能替代验收或 CPU／内存测量。

| 操作 | 预期 |
| --- | --- |
| Chrome／Edge 已登录，首次绑定 | 无需复制 Cookie，确认后显示真实账号，未自行开启监视 |
| 未登录后再登录 | 等待登录，随后自动跟随；普通匿名读取可用 |
| A 切 B、删除后立即重建 Cookie、同账号刷新 | 应用最终快照；迟到身份不覆盖，避免重复重连，同房间历史保留 |
| 明确退出、两种退出策略、匿名模式保存账号 | 旧凭据不用于直播；匿名继续或停止；匿名选择始终不携带账号 |
| 浏览器关闭、后台休眠、助手关闭后登录变化 | 不误退出，恢复后补偿；只保存本机快照，桥接退出，不弹出助手 |
| 助手重启、手动立即同步、刷新本机状态 | 最近快照被验证；状态未变化有结果；桌面刷新不假装唤醒浏览器 |
| 关闭／恢复跟随、通知失败、连续失败 | 设置待确认明确，有界退避；停止后不形成高频计时器或无界队列 |
| 多配置、换来源、断开后旧消息、扩展重装 | 单活动来源不被抢占，旧令牌失效，重装需重新配对 |
| 权限撤回、断网、403、异常身份资料 | 显示恢复权限或重试，不提交假的退出快照，不泄漏 Cookie |
| 主程序移目录、协议不匹配、缺文件、安装繁忙 | 稳定路径有效，需修复时清晰提示，重试不修改非自有注册项 |
| 卸载清除／保留凭据 | 仅移除自有组件，绑定均撤销；保留转手工来源；浏览器登录仍在 |
| 明文旧设置、迁移写入失败、损坏密文、不同用户 | 成功后无明文字段；失败保留原文件；恢复需明确确认且保留备份 |
| 大消息、旧序号、幂等重试、同时退出和更换来源 | 拒绝超限或旧绑定，不重复覆盖或撤销新来源 |
| 隐藏账号页、软件退出、反复切换账号、大量弹幕 | 释放头像与验证等待，无常驻桥接、无限重试，测量 CPU／内存是否稳定 |

## 开发发布

使用 PowerShell 7、Visual Studio WinUI 构建环境、.NET 8 SDK 与 Node：

```powershell
pwsh -NoProfile -File scripts/publish-browser-sync.ps1
# 再次发布必须使用新的非空目录名
pwsh -NoProfile -File scripts/publish-browser-sync.ps1 -ReleaseName browser-login-sync-next
```

脚本只编译、复制、核对文件并制作排除用户设置的 ZIP，不启动应用、桥接、扩展或安装程序，也不修改注册表或调用真实身份接口。
