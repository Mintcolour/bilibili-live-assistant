分支：`runtime-resource-budget`；基线：`1e683a7`，生产图片缓冲优化基线 `7efc710`。

## 已完成批次

- `61e0629`：优先完成用户追加的进房头像独立开关，Release x64 编译通过。
- 诊断 schema 5：保持 schema 4 全部字段，新增解码输入在用／峰值字节、开始／结束计数、原图尺寸组及解码档位、绑定／重绑调用与实际变化计数。分析脚本在旧字段缺失时返回 null。
- `measure-process-budget.ps1`：独立进程约 250 ms 采样，仅持有核对过可执行文件路径的进程句柄；记录私有工作集、私有提交量、总工作集、CPU、超限次数及计量自身 CPU 时间。不得据有限采样宣称不存在间隔内峰值。
- 隔离 StressApp 新增匿名真实直播模式，使用生产网络及 UI 路径，独立图片缓存和历史目录，不读取真实设置、Cookie 或历史库，不启动 BrowserHost。启动基准单独停留 60 秒，再连接直播；正式应用不增加启动延迟。

## 图片管线批次

- WinRT 解码输入使用可断开原始数组引用的只读流适配器，取消原正文到 WinRT 内存流的整份复制；输入持续存活至异步解码结束，关闭后断开正文引用。显示源仍拥有其底层 SoftwareBitmap，未提前关闭或手动释放 COM。
- 头像角色单独请求已核对的 `i0/i1/i2.hdslb.com/bfs/face/40位散列.jpg/png/webp` 缩略图，使用 64/128/256 档位、无放大和保留透明度的 PNG。含查询、已有变换、GIF 和未知路径保持原请求；一次有界原图回退。原事件 URL 不变。公开示例 300px 原图 79,435 字节，64px PNG 9,654 字节，128px 33,024 字节。
- 正文在当前下载／解码消费者之间共享，最多 2 路下载、32 个键；最后一个消费者离开后取消并移除，没有新增常驻原图缓存。解码仍最多 2 路，大图像素读取串行准入。诊断的 `bodies.bytes` 统计共享正文一次，`decodeInputBytes` 按解码消费者计量，两者不能相加。
- 动画显示只持有当前帧和一次正在上传的下一帧，切换后关闭旧显示源；不再逐步常驻全部 40 个 BitmapImage。编码动画资产及四路、10 FPS 规则保持。
- 已完成短时固定 PNG 隔离运行（180 秒、50 条/秒），未见解码失败；停止、停播、同房重启保留记录，换房清空断言通过。这不是长期内存验收。
- 新增确定性多尺寸 PNG/JPEG、透明双帧 GIF 和公开 WebP 素材生成脚本及仅监听 loopback 的测试服务。真实 HTTP 处理器覆盖已知长度、分块短读、取消及间歇 503；生产白名单和 TLS 不变。纹理种类有限，报告不将轮换 URL 数说成独立图像内容数。

StressApp 的入口及初始资源与正式 App 不完全一致；必须同时记录其自身 M0 与两倍基准约束，正式 160 MiB 上限不得随运行抬高。真实流量的吞吐、格式和显示条件仍需在对照报告中列出。

当前只完成上述实现、静态核对及隔离程序 Release x64 发布和 WinUI 原生运行库哈希核对。内存／CPU目标及显示兼容尚未验收，不标记整个计划完成。
