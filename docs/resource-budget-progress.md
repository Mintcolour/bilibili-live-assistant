## 图片管线批次

- WinRT 解码输入使用可断开原始数组引用的只读流适配器，取消原正文到 WinRT 内存流的整份复制；输入持续存活至异步解码结束，关闭后断开正文引用。显示源仍拥有其底层 SoftwareBitmap，未提前关闭或手动释放 COM。
- 头像角色单独请求已核对的 `i0/i1/i2.hdslb.com/bfs/face/40位散列.jpg/png/webp` 缩略图，使用 64/128/256 档位、无放大和保留透明度的 PNG。含查询、已有变换、GIF 和未知路径保持原请求；一次有界原图回退。原事件 URL 不变。公开示例 300px 原图 79,435 字节，64px PNG 9,654 字节，128px 33,024 字节。
- 正文在当前下载／解码消费者之间共享，最多 2 路下载、32 个键；最后一个消费者离开后取消并移除，没有新增常驻原图缓存。解码仍最多 2 路，大图像素读取串行准入。诊断的 `bodies.bytes` 统计共享正文一次，`decodeInputBytes` 按解码消费者计量，两者不能相加。
- 动画显示只持有当前帧和一次正在上传的下一帧，切换后关闭旧显示源；不再逐步常驻全部 40 个 BitmapImage。编码动画资产及四路、10 FPS 规则保持。
- 已完成短时固定 PNG 隔离运行（180 秒、50 条/秒），未见解码失败；停止、停播、同房重启保留记录，换房清空断言通过。这不是长期内存验收。
- 新增确定性多尺寸 PNG/JPEG、透明双帧 GIF 和公开 WebP 素材生成脚本及仅监听 loopback 的测试服务。真实 HTTP 处理器覆盖已知长度、分块短读、取消及间歇 503；生产白名单和 TLS 不变。纹理种类有限，报告不将轮换 URL 数说成独立图像内容数。

StressApp 的入口及初始资源与正式 App 不完全一致；必须同时记录其自身 M0 与两倍基准约束，正式 160 MiB 上限不得随运行抬高。真实流量的吞吐、格式和显示条件仍需在对照报告中列出。

当前只完成上述实现、静态核对及隔离程序 Release x64 发布和 WinUI 原生运行库哈希核对。内存／CPU目标及显示兼容尚未验收，不标记整个计划完成。

## 概览与合成批次

`DashboardHistory` 维护四列独立内容／状态版本、未读／感谢／修订计数；礼物合并、裁剪、已读和清空同时维护账目。未变化列不扫描；纯状态变化更新已实现行的操作区。保留原记录数量、过滤、稳定槽位和阅读锚点，未过滤列表直接读取原列表，不再每批复制整列数组或建立临时保留集合。

复用行相同图片和身份保持租约；富文本逐段更新，保留表情控件并跳过相同尺寸／文字／徽章及 Image.Source 赋值。进房头像开关不触发普通弹幕图片释放。

三种浮窗的头像、表情和媒体到达通知按同一 UI 消息轮合并，每项最多一个待合成回调；不等待其他图片，不降低帧率。补充合并计数，并修正固定面板媒体异步回调捕获循环槽位的问题。Release x64 隔离发布和 SDK DLL 哈希核对通过；该批的运行、阅读锚点及长期 CPU 对照仍待完成。

## 对照工具修正

优化前混合低频基线 `resource-mixed-baseline-low` 已提前结束：外部 250ms 计量得到私有工作集峰值 245.61 MiB，2,574 个外部样本中 1,725 个超过 160 MiB；约 11 分钟观察不算完成一小时。约第 521 秒主窗口曾隐藏一次，对照报告明确保留该条件变化。结束前的明细初步显示累计分配速率约 6 MiB/秒，尚不能将所有差额归于图片或永久泄漏。

新增 `analyze-resource-budget.ps1`，单独报告 160 MiB／两倍 M0 约束，旧 180 MiB 分析工具保留给旧版证据使用。新工具结合外部计量、30–60秒启动中位数、三次独立启动、窗口状态、完整时长和保留断言判定；缺少证据标为 incomplete，任一观测超限即记录失败。单次 M0 仅作为暂定值，不抬高上限。

隔离构建的图片错误日志和可选性能日志改写到独立运行目录。正式应用路径不变；不读取、清除或修改已有用户日志。后续素材故障可以在隔离日志内核对。`resource-incremental-v4` Release x64 发布及两份原生 SDK DLL 哈希核对通过，正在单独执行阅读位置及生命周期短回归；尚未完成一小时内存验收。

`resource-incremental-short-v4`（3条/秒、180秒）已正常结束。外部采样峰值 137.72 MiB，未超过绝对 160 MiB，但单次启动中位 50.59 MiB，对应暂定两倍上限 101.18 MiB，仍判失败。生命周期保留／换房清空断言通过。独立错误日志仅有一次 HTTP 503，与素材服务故障注入一致；未见解码错误。阅读位置探针在低频 SC 数量不足时越界，该项不能判通过，已修正为有界等待有效样本。短测不能与11分钟旧基线峰值直接计算优化百分比。

## 压力策略候选

新增依附图片申请／释放及消息批次的进程资源观察，最多每秒一次，无空闲轮询。按绝对160 MiB的80%／90%／95%提升压力级别，恢复阈值75%／85%／90%，观察到连续低压后至少10秒才逐级恢复。它不保证 WinUI、驱动和分配器的总量，报告仍独立执行更严格的 M0 检查。

闲置显示源预算由8 MiB／256项降至4／128、2／64、1／32；不夺取可见租约，不缩减24 MiB像素缓存。最高压力仍保留少量闲置源，因为同一UI批内的可见行重绑会传递相同图片，清到零会增加重复上传。高压力下像素提取和显示源转换改为可取消串行，正常保留两路，不改变图片质量、帧率及消息数量。这些策略需观察命中率、上传次数及延迟，不能仅据缓存减少宣称收益。

无长度／分块正文候选改用有上限的16 KiB短分段，最终只复制一次至精确长度正文，去掉 MemoryStream 扩容产生的多个临时大数组。不新增常驻原图池；2 MiB上限、短读、取消和超限探测保持。新增在用／峰值分段暂存计数，和完成后的共享正文是不同生命周期，不与解码消费者字节重复相加。

测试工具增加独立启动基准模式、有效DPI及构建程序哈希；三次启动基准必须匹配同一程序、SDK、DPI与显示配置。以上候选正在隔离编译和短回归，未完成长期、动画、隐藏恢复及真实日志验收。
