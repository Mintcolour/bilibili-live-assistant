# 概览榜单与可视化设置

2026-10-13，新版发布目录：`artifacts/releases/visual-dashboard/`。继承 `rich-rank` 版设置，不启动软件、不运行测试，由用户手动验证。

## 概览

- 顶部直接输入房间号或直播间链接，点击“开启监视”；运行期间锁定输入，停止后可换房。齿轮中选择匿名读取，沿用原有认证和自动重连逻辑。原单独的直播间导航入口合并到概览。
- SC 列上方默认 60%，下方榜单 40%；拖动中间分隔线改变比例，点击“榜单”折叠或展开，布局保存到设置。弹幕、互动、礼物列继续使用原有布局。
- 高能榜、大航海总榜／月榜／周榜可以切换。成员显示名次、头像、昵称、粉丝牌和大航海身份；头像及徽章遵循共享外观开关。高能榜显示接口原始贡献值，不在单位未经确认时换算成人民币；大航海显示接口提供的累计陪伴天数，周／月排序不意味着天数也是该周期内的天数。
- 榜单默认可见时每 60 秒刷新当前类型，可在可视化设置的概览分类调整为 15–600 秒，也可手动刷新。每页最多 30 条，大航海第一页还包括前三名；“加载更多”按需取下一页，总共最多保留 200 人。刷新已经加载的页时顺序请求，不预取剩余页；数据没有变化时保留可见行。
- 折叠榜单、离开概览、最小化或隐藏主窗口时，取消榜单请求并释放可见行及图片等待。重新显示后恢复；已有房间信息及悬浮榜单轮询继续按原节奏运行。请求失败保留上次快照并显示重试状态，不显示为一个有效的空榜单。
- 点击主播头像展开统计卡片：主播名、直播标题、大航海人数、粉丝团人数及牌名、高能人数、看过人数、点赞数，以及本次监视的人气曲线。缺失值显示“—”。人气与实时在线人数是不同指标，曲线明确标为人气；曲线只保留 240 个点，最短 15 秒采样一次，新一轮监视清空曲线。卡片关闭后停止绘制。

## 设置

顶部选择概览消息、普通弹幕、礼物、SC、进房或榜单；左侧是实时样式预览和桌面布局缩略图，右侧只显示当前类别的属性。窄窗口改成上下排列，避免左右面板互相遮挡。

字号、表情高度、速度、透明度、排版尺寸使用带数值的滑块；颜色使用带色块和十六进制输入的选色器。概览和悬浮预览分别复用实际消息组件、悬浮图文渲染器。滚动预览展示同样的图文与速度，使用 Windows 合成动画，其帧率不能作为实际分层悬浮窗的性能测量；滚动帧率设置仍应用到已有悬浮时钟。图片表情与头像继续共用有界缓存，不新增个人资料请求。

桌面缩略图显示各块屏幕与五类悬浮区域，拖动区域改变位置、拖动右下角改变尺寸。与实际悬浮窗共用默认布局和边界计算；精确坐标、尺寸仍可在辅助选项输入。布局在草稿中调整，保存后应用。解锁实际窗口并移动时，其保存的布局会同步回未单独修改布局的草稿。

类别切换保留草稿。“保存并应用”统一应用，“还原修改”恢复当前已保存值，“默认布局”只改布局草稿。“更多”中保留复制外观到所有悬浮区域和清晰简约预设；“保存并显示示例”会明确保存草稿后向悬浮窗发送示例。共享头像、粉丝牌和身份开关也可在各悬浮分类修改。

预览只在设置页与主窗口可见时播放。隐藏／退出页面时停止动画、取消图片等待、释放预览资源；预览位图只在参数或图片改变时更新，连续滑块变化合并到一次延迟绘制。

## 数据依据与验证范围

大航海接口字段与排序参数参考公开资料：

- [大航海成员接口说明](https://github.com/ILoveScratch2/bilibili-api-collect-new/blob/bee4521ead2aa3699d0c77455616101a241c123f/docs/live/guard.md)：`topListNew`，`typ=3/4/5` 对应周／月／总排序，第一页有独立前三名，`accompany` 为陪伴天数。
- [已有客户端实现](https://github.com/lanyangyin/OBSscripts-bilibili-live/blob/68f0452d809556b5fd913e5616e59e2a5b2feafd/function/api/Generic/get_guard_list.py)：用户身份位于 `uinfo`，兼容现有图文解析。
- [房间统计字段的消费代码](https://github.com/myonlydou/sxwz-subscriber/blob/28d738500a27c6ffa9698d8cfbea1df151211bc3/sxwz-subscriber-app/app/features/subscriber/components/app-subscriber.tsx)：粉丝团人数、点赞数等复用现有房间信息响应，不增加专门请求。

按用户要求只做静态检查及 Release 发布编译，没有运行单元、界面、直播间或性能测试。接口的当前可用性、匿名条件下返回的字段及实际显示效果仍需用户手动验证，不将缺失字段伪造成真实身份或数值。
