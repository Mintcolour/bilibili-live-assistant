# 图文概览

2026-10-13 当前版本增加概览连接入口、SC 下方的高能／大航海榜单、主播统计卡片与可视化设置，详见 [新版使用说明](visual-dashboard.md)。以下保留此前版本的布局和修复记录。

### 礼物合并修复

`artifacts/releases/gift-merge-overview/` 修复概览礼物一直逐笔新增消息行的问题。概览与悬浮窗共用“显示设置 → 礼物 / 上舰 → 礼物合并窗口”，默认 3 秒，0 为关闭。相同正值 UID、相同礼物和币种从第一笔起计时；概览即时更新原行的数量和金额，悬浮窗在窗口结束后一次滚动播报。超过窗口的后续礼物另起一组，已有历史不追溯合并。

合并保留记录 ID，并通过内容修订号刷新发生变化的可见行；其他行继续复用。新礼物加入已读／已感谢的一组时，该组恢复未读、未感谢。数量和金额同步写回消息元数据，防止多次合并后统计与文字不一致；数量溢出时封顶。

匿名或遮挡昵称不能用于识别同一观众。缺少正值 UID 时，只在相同非空交易 ID 且礼物／币种相同的情况下合并；不同正值 UID 始终分开。平台既不提供 UID 也不提供相同交易 ID 时，即使昵称相同仍逐笔显示，不推断为同一人。没有加入额外请求、定时器或无界用户缓存，历史继续受记录上限约束。

该发布继承 `visual-dashboard` 的设置，仅完成静态检查、Release 编译和发布文件检查；没有启动软件或运行测试，真实消息的显示效果由用户手动验证。

图文概览首版发布到 `artifacts/releases/overview-rich-messages/`，悬浮文字与卡片修复版位于 `artifacts/releases/overlay-readable/`，随后悬浮画面提交修复版位于 `artifacts/releases/overlay-visible/`。仅进行了 Release 编译和发布检查；
按用户要求未运行自动测试、UI 测试、直播间测试或性能压测，实际显示与占用由用户手动确认。

2026-10-12 概览布局优化版位于 `artifacts/releases/dashboard-compact/`，包含此前悬浮显示修复；继续只做编译与发布检查。

随后按钮点击修复版位于 `artifacts/releases/dashboard-controls/`：使用独立系统标题栏，页面状态栏和操作按钮位于标题栏下方，不与关闭/最大化/最小化或拖动区重叠。图标按钮使用透明画刷覆盖完整点击区域，顶栏按钮 32 px、列头及单条操作按钮 28 px；鼠标可点击图标周围的按钮空白。

启动修复版位于 `artifacts/releases/dashboard-startup-fixed/`：移除关闭内容扩展后对 `PreferredHeightOption` 的赋值，使用系统标题栏默认高度。该属性要求 `ExtendsContentIntoTitleBar` 为 `true`；按钮点击修复版的启动崩溃日志记录了 `0x8007139F` 无效状态异常，与这处调用不符合前提一致。保留独立标题栏及按钮修复，仅做编译与发布检查，启动和点击效果由用户手动确认。

## 布局与操作

- 主窗口现有概览升级为三列：普通弹幕、醒目留言 SC、礼物/上舰；左侧下方独立显示进房/关注等互动。
- 移除重复的“直播控制台”“直播概览”标题，侧栏默认折叠，可用菜单按钮展开。页面使用固定深色主题，缩小外边距，消息列表填满剩余高度。
- 顶部为一行图标状态栏：连接状态色点、房间号、时长、可获取的人气/看过及前三名高能榜。图标提示保留完整状态、连接方式和直播标题；右上角详情按钮显示房间详情及本次接收、省略和未读淘汰统计。
  时长随原有房间信息轮询更新，默认约 30 秒一次；缺失数据不推算。窄窗口缩起榜单文字及部分指标，提示和详情中仍可查看。
- 拖动两条列间分隔条调整宽度，拖动左列横向分隔条调整弹幕/互动区高度，松开时保存。右上角“更多”提供“均衡列宽”，比例为弹幕 1.4、SC 1、礼物 1.2；保留用户已有列宽，直到拖动或选择均衡。
- 各列使用单行标题栏，保留总数与未读数字；向上箭头回到最新，筛选图标仅看未读，勾选图标全部标为已读。图标均有提示与辅助功能名称。
- 已在最新位置或没有消息时，回到最新按钮变灰；没有未读消息时，全部已读按钮变灰。未读筛选开启时保持高亮，筛选无结果显示“没有未读消息”；开启筛选后即使列表清空仍可关闭筛选。回到最新会定位到第一条保留记录，内部滚动控件尚未缓存时也通过列表定位执行。
- 头像、粉丝牌、舰长/提督/总督/房管标识默认显示，各自可关闭；缺失头像显示占位，缺失身份标识省略。
- 礼物/SC 的勾选按钮标已读，星形按钮标已感谢；黄色点表示未读，实心星表示已感谢。双击消息仍标已读，列顶部保留全部已读与仅未读。
  已感谢同时标已读，不会因悬浮卡片消失自动标记或移除。
- 右上角表情图标“显示示例消息”生成本地图文示例并打开悬浮区；窗口图标控制悬浮区，详情图标显示房间与接收统计，“更多”保留清空记录、单条测试弹幕与手动高流量示例入口。
  示例不会向 B站发送消息，高流量入口只在用户点击后运行，离开概览/隐藏窗口时停止。

## 样式与保留

“显示设置 → 概览：图文样式、表情和记录上限”提供深色简约、圆角气泡、透明紧凑预设。
可调整概览字体、昵称/正文字号与颜色、文字/背景独立不透明度、背景颜色、行距、消息间距、内边距、圆角、
头像/徽章/小表情尺寸、大表情高度上限和概览刷新间隔。点击页面下方保存后生效。

默认启用“紧凑消息”：弹幕、礼物和互动使用无大背景的消息行，圆角粉丝牌、身份、昵称和正文同行并自然换行；头像为 24–32 px，间距至多 4 px，消息时间移到提示。SC 保留独立卡片，头像/昵称/金额和操作在卡片头部，正文另行展示，避免重复显示金额。
关闭紧凑消息可使用原有分行卡片，恢复可调的大头像、背景、内边距与间距。“深色简约”“透明紧凑”预设启用紧凑消息，“圆角气泡”预设使用分行卡片。字号、颜色、徽章、表情及记录设置继续保留。

| 分区 | 默认保留 | 可调范围 |
| --- | ---: | ---: |
| 普通弹幕 | 500 | 50–2000 |
| 礼物/上舰 | 200 | 20–1000 |
| SC | 100 | 20–500 |
| 进房 / 关注互动 | 15 | 1–15 |

进房 / 关注互动严格按接收顺序保留最近最多 15 条；旧设置高于 15 时自动限制到 15。其余分区达到上限先移除最早的已读/已感谢记录，再移除最早记录；移除未读礼物/SC 的累计数量在右上角详情里查看。
未读数量仅统计当前保留记录。记录只在本次运行中保留，切换房间或点击清空后移除；不保存观众历史到磁盘。
悬浮区域的显示开关只控制悬浮展示，概览仍接收各类记录。

## 表情与资源

### 表情排版与布局刷新

修复版位于 `artifacts/releases/emote-layout-fixed/`，保留进房展示和此前启动修复。
大表情在昵称/徽章下方使用独立内容块，保持图片比例，并随可用列宽缩小；不再与昵称共享文字基线。
普通行内表情继续随正文换行，行高允许容纳图片。圆角气泡和 SC 正文采用同一内容构建方式。
图片在加载前预留尺寸，下载完成时不改变行高；默认静态和原有动画数量/帧率限制不变。

消息行短暂卸载时保留静态首帧，暂停动画；经过一个 UI 调度回合仍未挂载时释放图片引用，重新挂载时恢复图片及动画注册。
只有列表真正回收、替换消息或页面释放时才销毁控件资源。加载中断后，即使已有图片数据但尚无可见图片，也可在重新加载时恢复首帧。
保存列宽、互动区高度、刷新间隔或历史上限不重建外观未变化的消息行，避免拖动后重复解码与表情丢失。
共享图片缓存和列表虚拟化继续使用原有上限，不添加重试轮询或新的常驻定时器。
“显示示例消息”中的大表情带粉丝牌，可用于手动确认昵称、表情和拖动后的显示。仅做 Release 编译和发布文件检查，未启动软件或运行自动测试。

### 图片内存持有与回收

`artifacts/releases/image-memory-fixed/` 补充图片内存优化。此前每个消息控件分别解码相同 URL，暂时卸载后仍保留图片；共享图片数据缓存的 24 MiB 预算不涵盖这些 UI 图片引用，不能当作进程内存上限。
概览同 URL、同解码宽度的静态首帧共享 `BitmapImage` 和进行中的解码，页面首帧缓存按解码像素估算最多 8 MiB / 256 项，最多 32 个进行中的请求。该预算同样不包含可见控件仍引用的图片、WinUI/运行时和悬浮画布。
离开布局的图片在下一 UI 调度回合释放控件引用，重新挂载从缓存恢复；异步完成时检查资源代次，避免旧解码覆盖重新加载的图片。
列表明确管理已创建卡片，记录移除、回收、替换和页面释放都会销毁相应图片及内容树，包括无法通过 `ContainerFromItem` 查询的脱离容器。
不增加常驻轮询、强制 GC 或后台测试。仅静态检查、Release 编译和发布；尚未实测内存增长趋势，不宣称已证明无泄漏。

### 行内表情加载与进房记录限制

`artifacts/releases/emote-queue-fixed/` 修复请求容量已满被当作图片失败的路径。原共享下载请求达到 32 个、或 UI 首帧解码达到 32 个时会立即返回空图片，消息留在 `[白眼]` 等文字占位且不会在空位释放后继续加载。
概览图片现在等待空位并自动继续加载：下载请求由实际完成通知唤醒，UI 首帧解码使用异步信号量，无计时轮询。消息实际卸载或回收时取消该控件的等待，已被其他消息共享的下载/解码不受影响。下载仍最多 2 个并发、32 个共享进行中请求；UI 首帧解码仍最多 32 个，原缓存预算不变。
CDN 请求补充 B站直播页 Referer，不附带账号 Cookie。真实下载、格式解码失败仍保留原始文字占位与失败冷却；本轮没有实测截图里的图片 URL，不能保证所有网络/格式问题都由容量等待修复。
互动记录默认 15 条、设置范围 1–15，始终移除最早记录；列表同步移除旧卡片并清理头像/图片引用。共享缓存仍按其预算淘汰，并不表示每删除一条记录，整个进程工作集会立刻等量下降。
仅静态审查、Release 编译及发布文件检查，未启动软件或运行自动测试。

### 行内图片主动加载

`artifacts/releases/inline-emote-fixed/` 将图片启用/释放移到消息行和虚拟化列表管理。新行绑定、旧行再次绑定及消息行加载时主动启用图片，不再依赖 `InlineUIContainer` 子控件的 `Loaded` 事件或 `IsLoaded` 判定才开始请求、应用首帧。
整个消息行仍在暂时脱离后的一个 UI 调度回合检查是否需要释放；列表回收、记录移除和页面释放继续取消等待并销毁图片引用。缓存已有图片可以在绑定时直接恢复，解码宽度使用所在列表/消息行的 DPI；没有增加轮询、预加载所有历史或扩大缓存预算。进房 / 关注仍最多保留最近 15 条。
实际下载、图片数据解码或 UI 首帧解码失败记录到 `%LOCALAPPDATA%/BilibiliLiveAssistant/image-errors.log`，文件最多 32 KiB，写满后覆盖。仅记录失败阶段、图片 URL 的哈希、CDN 域名、异常类型、HTTP 状态、HRESULT 及最多 12 字节的文件头；不记录弹幕内容、昵称、Cookie 或完整 URL。正常图片不写日志。
用户确认此前占位一直保持文字，不能视为仅加载延迟。本轮修正了子控件状态门槛并加入可定位实际失败的记录，但未启动软件或运行测试，尚未确认用户现场的最终触发原因。WinUI 列表加载事件异常的相关公开报告：[microsoft-ui-xaml #8841](https://github.com/microsoft/microsoft-ui-xaml/issues/8841)；该报告作为避免仅依赖加载事件的参考，不视为本次现场复现证据。

### 进房头像与专属进场

进房展示修复版位于 `artifacts/releases/entry-appearance/`，继承启动修复。
新版 `INTERACT_WORD_V2` 解码并保留 `uinfo.base.face`、头像框、粉丝牌、大航海身份和关系尾标；旧版 JSON 兼容 `uinfo` 与 `fans_medal` 字段。
普通进房使用圆形头像、粗体昵称、灰色提示和实际下发的关系图标/文字。不会根据 UID、勋章或本地历史推断“潜在粉丝”“回归”。

`ENTRY_EFFECT` / `ENTRY_EFFECT_MUST_RECEIVE` 在互动列表和悬浮互动区展示静态渐变进场条：身份徽章、粉丝牌、昵称和欢迎文字在同一行，支持平台静态背景图、头像框和昵称高亮色。无大航海身份时支持实际下发的荣耀等级和样式图标，图片失败回退等级文字。
仅收到这类事件时显示专属条，普通进房不会因为有粉丝牌而自动套用。普通进房和专属进场是不同事件，平台同时下发时可同时出现。
字体与大小沿用概览或悬浮区域设置；头像、粉丝牌和身份开关继续有效。平台未下发头像或资源下载失败时显示占位，不逐人调用资料接口。

悬浮互动区合并窗口内最多保留最近 3 条图文互动，多出的数量单独显示；不再因为超过 3 条就全部变成无头像的纯统计文字。
头像、框、关系图标和背景共用现有有界图片缓存，专属进场始终静态，不添加帧循环或轮询。
“显示示例消息”增加普通进房、回归标签和专属进场本地示例，标签仅用于示例。仅做编译与发布文件检查，未启动软件或运行测试。

协议字段依据：[blivedm 的 V2 模型](https://github.com/xfgryujk/blivedm/blob/dev/blivedm/models/pb.py)、[B站网页当前协议代码](https://s1.hdslb.com/bfs/static/blive/blfe-live-room/static/js/app.3f7250563d6495ab0c32.js)（2026-10-12 读取）、[进场消息采集资料](https://github.com/pskdje/bilibili-API-collect/blob/main/docs/live/message_stream.md#用户进场特效-entry_effect)。字段是平台实际下发内容的兼容解析，不保证匿名模式始终提供完整资料。

弹幕解析保留 `info[0][13]` 大表情、`info[0][15].extra.emots` 行内表情和下发的头像/徽章。
同时接受对象或 JSON 字符串字段，保留文字占位作为图片失败回退，不为每条消息额外查询用户信息。
用户资料完整程度取决于 B站实际下发数据；匿名 UID 0 不归并为同一观众。

默认只显示静态首帧。开启动画后，概览最多同时播放 4 个可见表情，最高 10 帧/秒，单图最多 40 帧、解码尺寸最长边 256。
GIF 使用完整画布合成，其他格式通过 Windows 图片解码器识别；系统不支持多帧或帧数超过限制时显示静态，
不能解码时显示原始占位文字。只有获准播放的可见表情加载多帧，帧图缓存后复用，不在每帧重新解码。
隐藏窗口、离开页面或移出视口时暂停并释放控件中的多帧资源。
桌面滚动弹幕与固定卡片使用静态头像、徽章和图片表情组合缓存，保留各悬浮区域已有字体与时间设置。

资源下载限 2 个并发、最多 32 个共享待处理请求，单文件最多 2 MiB；同 URL/显示方式共享请求。
下载与正文读取有超时，失败冷却 5 分钟。共享内存缓存预算 24 MiB（包括帧解码尺寸估算），
磁盘缓存最多 128 MiB / 512 项，位于 `%LOCALAPPDATA%/BilibiliLiveAssistant/image-cache/`。
可见控件另保留正在显示的图片；上述缓存预算不是整个进程内存上限。
仅读取 B站图片 CDN，使用 HTTPS，不附带账号 Cookie；图片失败不会中断弹幕接收。

概览使用受约束高度的 ListView 虚拟化、默认 250 ms 批量更新和已有行复用。
空闲时刷新定时器停止，主窗口隐藏时不更新可视列表；这些是实现约束，不是本轮 CPU 实测结论。
紧凑排版不增加动画或轮询时钟，头部信息变化时更新对应提示；详细统计在点击详情时生成。
