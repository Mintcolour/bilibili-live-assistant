# 高频弹幕提示与下播自动停止

发布目录：`artifacts/releases/hot-phrases-live-stop`。继承 `compact-rank-scroll` 当前设置，旧目录保留。

## 显示与统计

- 概览弹幕列顶部、普通弹幕浮窗顶部、紧凑面板与 OBS 网页源增加“内容 × 次数”提示。前三项使用浅黄色底，其余使用浅灰底。
- 统计接收时刻最近 60 秒内的普通弹幕，整句重复至少 3 次，按次数降序显示前 5 项；原消息、历史和礼物／SC 统计保持原有规则。
- 匹配仅合并首尾与连续空白，保留大小写、标点和表情图片身份差异。纯表情也保留原标识文本。测试消息不参与真实统计。
- 共用一个有界统计窗口，至多保留 8,192 个到达记录、1,024 个不同内容键；极端拥堵时逐步移除最早的统计记录，结果只代表保留样本。超过 512 字符的长弹幕不参与提示，不影响原消息显示或归档。
- 每秒最多更新一次，内容不变时不通知界面。窗口为空时停止统计计时器；换房、清空概览和重新开启监视时重置。
- 普通浮窗为提示预留顶部空间；狭窄或矮窗口只显示能容纳的条目。提示位图仅在内容或尺寸变化时重建，隐藏和到期时释放。紧凑面板关闭消息列表时隐藏高频提示。
- OBS 增加 `.bla-hot-phrases`、`.bla-hot-phrase`、`.bla-hot-text`、`.bla-hot-count` CSS 类，可继续通过自定义 CSS 修改样式。本地网页预览使用示例，实际统计不进入示例。

## 直播结束

- 接收到直播服务器 `PREPARING` 下播事件，或现有房间资料接口明确返回未开播／轮播状态时，自动停止当前监视，提示“直播已关闭，已自动停止监视”。
- 临时 WebSocket 断线、请求超时及缺失直播状态不视为下播，继续沿用自动重连。不增加额外轮询请求。
- 自动停止沿用现有停止和历史收尾流程，保留当前概览与历史供回看；不会清空正在阅读的记录。
- 停止操作在 UI 调度后获取连接锁，再次核对监视代次，避免回调等待自身或旧房间信号影响新房间。缓冲中的旧在线指标不能覆盖下播结果。
- 已取得可靠主播资料时，下播事件携带状态更新交给现有历史存档，记录已观察到的场次结束；不改变数据库结构。

## 已做与待验收

开发侧只做静态检查、Release x64 编译与发布文件核对，不启动软件、BrowserHost、浏览器或 OBS，不运行自动测试。未实测 CPU、内存和下播检测延迟。

请手动检查：

1. 60 秒内重复 3 次是否出现、是否显示前 5 项、过期后计数下降并消失；不同表情图片是否分别统计。
2. 概览列表／卡片、普通滚动／固定浮窗、紧凑面板及 OBS 中是否清楚可见，窄窗口下不遮挡原文；隐藏再恢复、换房和清空记录是否正常。
3. 实际下播是否自动停止并显示提示，当前记录是否保留，重新监视能否正常连接。
4. 临时断网是否只自动重连；旧房间延迟返回、快速停止后再开启、下播同时换房是否不会误停新监视。
5. 大量不同弹幕、长时间运行时 CPU 和内存是否保持稳定。编译通过不等同于运行或性能验证。

发布保留 ReadyToRun、DPI、SQLite、BrowserHost 和分析工具。设置应与上一版字节一致；分享包排除用户设置、历史库、日志、OBS 密钥及用户素材。
