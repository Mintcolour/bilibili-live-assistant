# 20:00 后运行日志分析与定向优化

## 本次证据

分析用户 2026-10-15 本地时间 **20:00:04–20:44:26（UTC+8）** 的 532 个真实样本。原始日志已在工作区 `artifacts/performance-20261015-2000-input` 留下本次只读副本，分析 JSON 和逐分钟 CSV 位于 `artifacts/performance-20261015-2000-*`，未打开用户历史数据库或设置内容。这些本地采样不进入 Git 或分享包。

CPU 为软件主进程按 20 个可用逻辑处理器归一化的百分比，不包含 BrowserHost、浏览器和系统 DWM。下列划分结合窗口状态，避免把长期空闲和后续活跃期混为一谈。

| 时段 | 观测场景 | CPU P50 | CPU P95 | 分配速率 |
| --- | --- | ---: | ---: | ---: |
| 20:00–20:17 | 主窗口隐藏，未创建浮窗，消息稀少 | 0.016% | 0.078% | 0.020 MiB/s |
| 20:17–20:21 | 主窗口出现、资料加载、开始出现浮窗 | 0.872% | 2.118% | 5.137 MiB/s |
| 20:21–20:44 | 主窗口大多隐藏，32 FPS 滚动浮窗持续显示 | 0.545% | 0.920% | 4.162 MiB/s |
| 20:44 后约半分钟 | 短时占用抬升 | 2.011% | 2.354% | 7.218 MiB/s |

20:00 后全段 CPU 最大 3.175%；私有内存从约 194 MiB 到最后约 470 MiB，工作集峰值约 573 MiB。但托管内存最后约 24 MiB、全段峰值约 77 MiB；20:21–20:44 私有内存回归斜率为 **-0.836 MiB/分钟**，并非持续线性增长。较大跳升在界面与图片开始活跃时，末尾短时抬升不足以判断泄漏。GC 的最近堆观测、原生图像资源和进程分配器保留空间都可能影响这些值，需要新版相同场景日志再对照。

## 热点与排除项

- **图片周转**：全段新增 9,079 次图片加载任务、7,537 次缓存淘汰、476 次 Gen2 回收。旧版 `loads` 同时包含磁盘读图和网络读取，不能据此说发起了 9,079 次下载。缓存始终受 24 MiB 预算约束，但头像统一最大 256 px 解码，小头像也产生较大的像素缓冲；浮窗 `TryGetFrame` 命中还未更新 LRU，热图会被按较旧顺序淘汰。这两条代码路径与频繁加载、淘汰和回收现象一致，尚不能量化它们各自占比。
- **滚动绘制**：普通弹幕累计绘制 45,979 次、总墙钟耗时约 159.3 秒，平均 3.465 ms，单次最大 54.052 ms。消息位图生成 13,784 次，平均 3.539 ms。主窗隐藏后滚动绘制仍是主要 UI 耗时来源之一。原调用把整幅消息图片交给 GDI+，屏幕外区域依赖目标裁剪；部分滚出或刚进入的长图片仍可产生额外的源图处理工作。
- **归档没有明显拥堵**：历史待写峰值 32 条、无归档遗漏或写入失败，全段存档批次累计耗时增加约 6 秒；UI 接收缓冲也无丢弃。没有依据优先降低归档频率或停止历史功能。
- **悬浮省略**：浮窗省略计数增加 9,292，含现有容量、轨道和过时等展示规则，不等同历史数据丢失，也不能全部归因为 CPU。本轮保持原规则，不靠少显示消息降低占用。
- **证据边界**：旧版 UI 快照通常比进程采样早约 5 秒，需容许过渡区间；耗时统计是墙钟，嵌套项不能相加为 CPU；单次回调间隔最大 235.6 ms 也不能直接定位为某一段代码。

## 本版修改

1. 图片增加 64 / 128 / 256 px 解码档位。概览按实际显示尺寸与 DPI 选择档位，浮窗头像按物理像素尺寸选择档位；媒体、浮窗大表情和装饰资源保持原最大档位。较大缓存及进行中请求可供较小请求共享，反向不复用不足的尺寸；切换到更高 DPI 时重新取得足够像素。所有档位合计仍限制在 24 MiB，新增最多 1,024 项，磁盘 128 MiB、两路下载和 32 个进行中任务限制继续保留。
2. 浮窗读取首帧同步更新 LRU，保护实际正在使用的热图；不增加常驻原生位图缓存，不强制 GC 或清空工作集。
3. 滚动图片同时裁剪源图区域，保留两个像素的插值边缘。原来的小数位移、双线性插值、字体、阴影、透明度和目标帧率继续使用。帧日志增加原始与提交源像素计数，便于检查减少了多少屏幕外源图处理。
4. 日志增加首帧命中 / 缺失、磁盘命中和网络请求计数，区分“重复解码”和“重复下载”。schema 2 尽量在同一时点采集 UI 与进程指标，UI 最多等待 200 ms，卡住时仍只保留一个采样请求。
5. 分析工具支持 `-FromTime` / `-ToTime`，可继续只检查某个时间之后的数据：

```powershell
./tools/analyze-performance.ps1 -FromTime '2026-10-15T20:00:00+08:00' -OutputPath ./performance-report.json
```

原始日志目录仍为 `%LOCALAPPDATA%/BilibiliLiveAssistant/diagnostics`，默认关闭、每约 5 秒采样、总量最多 8 MiB。开启方式沿用左侧“性能诊断”。
