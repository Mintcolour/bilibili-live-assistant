# 低占用与稳定性

本项目后续功能以低 CPU、受控内存和长期稳定运行作为主要约束。

## 运行策略

- 正常使用优先 Release 构建。启动脚本默认使用 Release。
- 弹幕窗口没有文字时停止动画定时器；隐藏后清空并释放文字缓存。
- 有弹幕时以约 30 FPS 更新位置，活动弹幕达到 12 条后降为约 20 FPS，按实际经过时间计算速度。只刷新文字移动影响的区域。
- 弹幕文字只生成一次位图，每帧复用；每帧最多生成一条，只进入空闲轨道；移出屏幕后立即释放。活动位图最多 64 个，待处理消息最多 64 条。超长弹幕在悬浮层截断为 256 字符，避免不受控的位图大小。
- 悬浮文字填色与描边共用字形路径，生成后缓存。窗口复用预乘 Alpha 画布、原生 DC 与 DIB，以分层窗口提交受影响区域；窗口尺寸改变时重建画布，关闭时释放资源。固定事件区统一使用图文卡片，避免每帧创建字形和图片资源。
- 分层窗口的画面提交通过独立窗口消息驱动，首次显示、重新显示、内容变化和尺寸变化时主动请求；每个区域最多保留一次待执行刷新，并合并受影响范围。空闲状态不轮询，隐藏或窗口句柄销毁时清理待刷新状态和原生画布。
- 网络到 UI 的缓冲最多 256 条，默认每 100 毫秒批量处理，并随启用区域中最短的内容更新间隔调整（50–2000 ms）；没有待处理消息时停止定时器。概览默认每 250 毫秒批量更新，列表虚拟化并保留未变化的可见行；主窗口隐藏或最小化时暂停列表刷新。分区历史与图片预算见 [图文概览](dashboard.md)。旧混合历史 200 条仍兼容保留，但不驱动概览控件。
- 队列拥挤时按 SC、礼物/上舰、普通事件的顺序保留，省略较旧普通弹幕；普通弹幕扣除配置的批处理时间后等待超过 2 秒时省略。付费事件改为独立固定区域，详见 [分区显示规则](overlay-display.md)。概览显示收到量、消息缓冲省略量和悬浮层省略量；历史也受缓冲和容量限制。
- 音频采样和文件录制保持原精度。电平图每 100 毫秒显示这段时间的最大峰值，避免漏掉短峰值；界面复用画刷，不随音频回调次数不断创建控件资源。没有录音或回放时停止电平刷新，离开页面释放音频设备。
- 每个网络消息解析后及时释放 JSON 文档。网络接收等待数据，不使用忙循环；心跳和人气轮询默认间隔 30 秒。

## 验证方式

2026-10-12 图文概览、悬浮显示修复及概览紧凑布局版本只做编译/发布检查，未运行自动测试、UI 验证或性能测试。
下文 CPU 与内存数据属于之前的纯文字实现，不能作为图文版本或原生 Alpha 呈现版本的实测结果。

测量同一机器、相同窗口大小和显示状态下的 Release 版本，分开记录：

1. 弹幕关闭、无录音和回放。
2. 弹幕开启但无文字。
3. 固定数量和频率的移动弹幕，以及全部移出屏幕后。
4. 录音、回放和离开音频页。
5. 高事件量及长时间运行时的内存、句柄数量。

```powershell
$runningApp = Get-Process -Name BilibiliLiveAssistant.App
pwsh -NoProfile -File scripts/measure-cpu.ps1 -ProcessId $runningApp.Id -Seconds 30 -OutputPath artifacts/cpu.json
```

CPU 百分比由进程 CPU 时间差除以采样实际时长和逻辑处理器数计算，报告平均值、P95 和峰值。
任务管理器的显示方式与采样窗口可能不同；UI 操作、弹幕、网络收包、音频采样和垃圾回收仍可能产生短暂波动，不能承诺 CPU 永远保持一个固定数值。
比较时不要同时运行两个测试版本、截图工具或构建任务。先预热，分别测空闲和负载；性能结论应附测试条件和测量数据。

## 2026-10-09 悬浮层对照

在本机 20 个逻辑处理器上，使用链接实际 `OverlayWindow.cs` 的独立 WinForms 测试进程，
固定窗口为 1280×300，顺序运行修改前后版本各 30 秒；每秒采样一次进程 CPU 时间。
先空闲 6 秒，每秒插入一条测试弹幕共 8 秒，随后等待 10 秒，最后再次空闲 6 秒。
该测试隔离了 WinUI 主页面、直播网络与音频；测量驱动本身每秒唤醒一次。

| 阶段 | 修改前平均 CPU | 修改后平均 CPU | 修改前峰值 | 修改后峰值 |
| --- | ---: | ---: | ---: | ---: |
| 初始空闲 | 0.3251% | 0.1357% | 0.8640% | 0.2348% |
| 每秒一条弹幕 | 0.6166% | 0.3121% | 1.7245% | 0.5508% |
| 弹幕结束后的空闲 | 0.4433% | 0.0519% | 0.9412% | 0.0786% |

修改前，即使活动条目为零动画定时器仍在运行；修改后空闲时关闭。
移动速度已修正为按实际时间计算，因此相同事件输入下，新版文字在屏幕停留时间会与原版有所不同。
这是一组短时对照，不构成对完整软件、不同屏幕尺寸或高流量直播间的性能承诺。
本机原始记录保存在忽略提交的 `artifacts/performance/before.json`、`after.json` 和 `comparison.json`。

自动运行检查确认：空闲不启动动画、单条事件恢复动画、活动位图最多 64 个、隐藏释放缓存、
滚动速度与经过时间一致，以及文字移出后自动停止定时器。

更新版启动后，主界面收起、未连接直播间、没有录音或回放时，再对完整软件进程采样 20 秒：
平均 CPU 为 **0.008%**，P95 为 **0.075%**，峰值为 **0.077%**。
记录位于 `artifacts/performance/app-background.json`。
这与主窗口可见或正在处理弹幕的负载条件不同，应分开看待。
此前一段整进程测量期间用户发送了测试弹幕，`app-idle.json` 的文件名不准确；该记录属于包含操作的负载样本，未用于空闲结论。

## 2026-10-09 高流量弹幕对照

使用 [WinUI 实机压测程序](../tests/BilibiliLiveAssistant.StressHarness/README.md)，直接链接正式应用的主窗口、ViewModel 和悬浮层。
同一台机器，20 个逻辑处理器，Release，主窗口 1100×720 可见，悬浮层 1920×360，默认 8 轨道、120 px/s。
本地事件源绕过网络解析和音频，模拟每 50 条一条礼物或醒目留言；CPU 记录覆盖整个测试进程。
每秒采样，平均值按实际采样时长加权；下面峰值均为一秒左右窗口的测量值。

| 阶段 | 修改前平均 CPU | 修改后平均 CPU | 修改前峰值 | 修改后峰值 |
| --- | ---: | ---: | ---: | ---: |
| 每秒 10 次测试点击，10 秒 | 1.303% | 0.620% | 2.321% | 1.013% |
| 100 条/秒，15 秒 | 1.238% | 0.696% | 2.025% | 1.463% |
| 1000 条/秒，15 秒 | 2.764% | 0.944% | 3.408% | 1.404% |
| 一次突发 3000 条，观察 5 秒 | 1.238% | 0.542% | 3.367% | 0.927% |

首轮修改前输入 19,600 条、修改后 19,598 条（实际定时调度存在微小差异）。
峰值工作集由 206.97 MiB 降到 188.38 MiB，峰值私有内存由 157.96 MiB 降到 120.33 MiB；
结束工作集为 183.52 MiB，私有内存为 117.15 MiB。Gen2 回收次数从 9 次降到 1 次。
峰值/结束句柄分别为修改前 1193/1148、修改后 1206/1204；这组短时数据不能证明长期无泄漏。
新版活动弹幕采样最大 38 条，历史最多 200 条，第 72.63 秒开始活动数归零，后续空闲停止动画。
最后十秒仍包含付费弹幕的移动尾段，不能全部当作空闲 CPU。

降低负载的一部分来自减少实际显示数量：首轮新版消息缓冲省略 2824 条，悬浮层另省略 16,673 条。
有界队列和消息过期确保不会因大量输入形成长期排队；无法在这个模式下显示每一条弹幕。
这组结果用于确认突发渲染和界面更新开销下降，不代表真实直播网络解析、所有屏幕尺寸或长期运行的性能保证。
基线记录为 `artifacts/stress/run-before/stress-results.json`，首轮新版记录为 `artifacts/stress/after-first.json`。

第二轮使用相同输入，补充记录待处理数和动画状态（`artifacts/stress/run-after-verified/stress-results.json`）：
1000 条/秒平均 CPU 为 0.909%，峰值 1.251%；100 条/秒平均 0.774%，峰值 1.244%；
每秒 10 次测试点击平均 1.233%，峰值 1.953%；突发阶段平均 1.025%，峰值 1.165%。
可见点击场景存在明显运行间波动，不能把首轮 0.620% 当成固定值。
所有采样都满足历史 ≤200、活动位图 ≤64、UI 缓冲 ≤256、悬浮层缓冲 ≤64；
第 80.67 秒两级缓冲和活动弹幕均为零，动画定时器停止。
第二轮峰值工作集 210.21 MiB，私有内存 134.86 MiB，结束为 208.25/132.72 MiB，
Gen2 回收 1 次，峰值/结束句柄为 1233/1223。
两轮工作集存在差异，因此当前证据支持 CPU 和处理量受控，不能宣称工作集在每次运行中都会降低。

正式 Release 自包含发布版也通过 Windows 界面验证：概览可见压力测试按钮和省略计数，
点击后自动打开悬浮层、按钮变为停止，30 秒后自动结束并恢复按钮。
此次 UI 定时器实际产生 2750 条，悬浮层省略 2685 条，消息缓冲省略 0 条。
按钮的 100 条/秒为目标频率，实际频率受 UI 定时器调度影响；前述 100/1000 条每秒的对照使用后台事件源。

## 2026-10-12 滚动流畅度优化（未实测）

旧分类滚动版使用 WinForms 33 ms 动画定时器，普通弹幕达到 12 条后降到 50 ms，即目标约 30/20 FPS；UI 消息调度还会影响实际间隔。这是代码中可确认的流畅度限制，上文旧版 CPU 数据不适用于本次改动。

- 四个滚动窗口共享一个动画时钟，默认 60 FPS，可选 30、120 或跟随屏幕刷新率（最高 240），以普通弹幕窗口所在显示器为准。没有滚动消息时阻塞等待，不持续轮询。
- 后台线程结合 DwmFlush 与高分辨率可等待计时器控制提交节奏，不让 UI 线程等待 DWM，不调用修改系统全局计时分辨率的 timeBeginPeriod。
- 最多一个待处理帧，繁忙时不会排队重放旧回调；根据实际时间计算位移，异常长暂停后的单帧位移限制在 100 ms。
- 帧更新后直接提交画面；保留分离轨道的重绘区域，最多 32 个，超过则合并。原生提交仍使用覆盖这些区域的外接矩形。
- 滚动使用小数坐标和双线性采样，避免高刷下被整数坐标量化成重复位置/一像素跳动。文字与图片继续复用位图，不在每帧重新生成字形。
- 空闲、隐藏、切房时取消相应帧订阅；退出唤醒并清理后台等待，不在 UI 线程同步等待 DWM 返回。

当前仍是软件位图绘制加 Windows 分层窗口呈现，不能将此版本宣称为 GPU 独立动画。提升帧率会增加活动绘制开销；默认 60 FPS 用于兼顾低占用，高刷选项供用户按实际效果选择。图片缓存、待播数量、进房三条和礼物/SC/榜单计时规则保留。

发布目录为 `artifacts/releases/overlay-smooth/`。只做静态检查、Release 编译/发布，不启动软件或运行测试，未记录新版本的实测 FPS、CPU 或内存数据。
