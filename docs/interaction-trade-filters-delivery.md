# 互动显示修复与礼物／SC筛选排序

本版修复概览互动区有计数但无文字，并增加概览、历史的礼物／SC筛选排序。性能目标仍未达标：42062真实直播约20分钟的隔离运行中，私有工作集观察峰值185.32 MiB，超过160 MiB；本包不能视为内存问题已解决。

## 互动显示修复

互动历史最多保留15条。突发消息整批替换记录时，原实现会提前清空旧记录对应的卡片并移除容器映射；但列表复用相同RowSlot，不一定再次触发容器内容变化通知，导致新记录无法重绑，出现计数正常而内容空白。

现在先同步槽位再重绑已实现的卡片，保留容器生命周期归属。新增诊断cardsWithText只记录实际绑定文字的卡片数量，不记录文字内容。进房头像开关、关注、历史容量与浮窗播报规则保持原设置。

## 筛选与排序入口

- 概览礼物、SC列头点击漏斗按钮。礼物可选普通付费、免费、上舰及完整礼物名称；SC可设最低／最高金额，单位元，留空表示不限。支持组合“仅显示未读”。
- 排序支持时间最新／最早、单条合计金额升序／降序；礼物另有数量降序。未知金额始终排最后，同金额按接收时间最新。概览中的礼物合并后使用合计数量与金额，缺失价格保留未知。
- 漏斗变金表示启用条件或非默认排序，列头显示匹配数／当前保留总数。可一键重置，偏好随软件设置保存。概览筛选只作用于当前保留记录，尽量保留阅读锚点。
- 历史先选择主播、场次和日期，再选“礼物／上舰”或“SC”，点击“筛选与排序”。其余UID、昵称、关键词和监视记录在“更多条件”弹出面板中。查询按钮和分页按钮保留可见位置。
- 历史在数据库所选范围内筛选、排序后按100条游标分页；匹配数与列表使用相同条件。礼物名称按完整名称精确匹配，不做模糊匹配。
- 筛选不删除记录、不改变底账统计，也不影响浮窗。礼物仍在显示合并前归档。不修改数据库版本、账号流程或原有显示参数。

## 已完成的核对

- Release x64隔离构建与静态diff核对通过。
- 互动突发替换核对8组，每组30条，均保留15条互动；3张已实现卡片均有文字。该项使用无图片配置，不能当作头像开关的完整视觉验收。
- 最终筛选核对30项通过，隔离写入480条记录，覆盖分类、金额／数量排序、相同排序值、未知金额、跨100条分页、完整名称、SC范围、概览未读组合、偏好序列化和历史页基本查询。
- 已人工查看125% DPI隔离窗口的概览、历史及SC金额编辑器渲染截图；不代表所有DPI与实际交互均已验收。
- 验证使用独立StressApp、独立历史与图片缓存；未启动正式App或BrowserHost，未读取真实Cookie或用户历史库。正式包设置只复制并比对哈希。

## 42062真实直播资源记录

匿名接收约20分钟，收到4726个事件，归档4509条；统计事件与消息归档范围不同，差值不能当作遗漏。归档丢弃、写入失败均为0。概览可见样本中互动卡片始终有文字，未再复现空白。

外部约250ms采样4507次，私有工作集峰值185.32 MiB，2964个样本高于160 MiB。外部采样晚约57.5秒开始，未覆盖完整启动和流量区间。主窗口运行期间曾被隐藏，不能算全程“概览＋浮窗同时显示”验收；已采集的可见样本峰值164.57 MiB，也已超过目标。CPU P95约0.91%（按20个逻辑处理器归一化），远程桌面返回32 Hz，不能与本机60／165 Hz直接比较。

约185.02 MiB的UI采样峰值处，托管内存约40.41 MiB、GC堆约47.57 MiB，静态像素缓存约16.26 MiB；主窗口已隐藏，共享WinUI显示源计数为0。运行末尾显示源创建／释放均1136次，租约、显示源及待创建任务归零。由此不能把本次高占用全部归因于未释放共享显示源；这些诊断也不覆盖WinUI、驱动及原生分配器的全部内存，不能简单相加视作总内存归因。

本轮修复已证实的列表复用错误，没有为追求160 MiB而裁剪工作集、强制GC或降低画质、帧率、容量。长期内存稳定性及真实本地刷新率下的CPU仍待进一步分析和人工验收。

开发证据保留在artifacts/memory-soak下：interaction-burst-proof、trade-filter-layout-proof和live-42062-interaction-v1。诊断与测试数据不进入分享包。
