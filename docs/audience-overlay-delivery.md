# 人数趋势与浮窗直接调整修复

分支：`audience-overlay`，基线为 `trend-overlay` 的 `3aaabf0`。发布到独立目录 `artifacts/releases/audience-overlay`，完整继承 `trend-overlay/settings.json`。

## 修改内容

- 概览头像展开的趋势改为高能榜返回的总人数，概览人数摘要、固定面板和滚动播报使用相同来源；人数使用人物图标。看过仍独立显示，未知人数显示“—”。只使用现有采集结果，不增加请求。
- 本次曲线保留最多 240 个实际人数采样，断线不连成连续曲线。保留历史原有人气字段，不改写既有存档。
- 历史页默认加载已监视主播，恢复可见时补上未完成的初次加载。主播加载与右侧日期／页签筛选取消分离；每批 200 位，更多主播可继续加载，清空搜索恢复默认列表。头像仍仅加载可见行。
- 移除实际浮窗的常驻说明条、起始行、容量、待播数量和点击说明。普通网格仅保留实际重复次数，SC 不再占一行显示操作说明；未展示记录移到编辑时的类型菜单。
- 概览和托盘的浮窗调整开关现在允许直接移动、缩放和切换各区域显示类型，不受保存的布局锁拦截。编辑时显示顶部操作与边角，完成后恢复穿透；拖动结束保存位置尺寸，选择类型后立即保存。
- 沿用受保护的定时礼物／上舰／SC 卡片、各类停留时间、有界队列、缓存和图片释放规则；固定面板空闲时不增加绘制循环。

## 交付验证

仅做静态检查、Release x64 编译、发布与文件核对，不启动软件、不运行自动测试、不读取用户实际数据库。核对 ReadyToRun 程序集、BrowserHost、SQLite 8.0.32、AMD64、PerMonitorV2、继承设置的 SHA256 和 ZIP 内容。证据：`artifacts/audience-overlay-verification/release-verification.json`。

## 手动验收

1. 在真实房间对照高能榜总人数，查看头像曲线和浮窗人数；没有总人数时显示未知，不能回退到人气或可见成员条数。验证看过人数仍单独显示。
2. 首次打开历史、最小化后恢复、切换日期和页签，主播列表无需搜索即显示；搜索并清空、继续加载、删除主播后刷新均正常。
3. 普通列表、网格、礼物、SC 和榜单浮窗不再显示常驻说明条；空窗口在非编辑状态透明。
4. 从概览或托盘进入调整，拖动各区顶部空白处和边角，切换显示类型，点击完成后鼠标穿透；重开软件检查位置、尺寸、类型保留。窄区域和不同 DPI 下检查命中范围。
5. 编辑结束后列表、完整 SC、未展示记录及网格悬停／隐藏功能符合预期；切换模式、换房、隐藏和退出后资源释放正常。

编译与文件核对不代表运行效果和性能已通过实机验证，仍由用户手动确认。
