## 图片分配线索

只读检查当前磁盘缓存文件的长度和格式头，不记录图片地址、账号或消息：512 个文件，约 51.56 MiB；其中 JPEG 462 张、WebP 35 张、PNG 14 张、GIF 1 张。可读出尺寸的 477 张中，430 张长边超过 256 像素、12 张超过 1024 像素，最大图像按 BGRA 原始尺寸估算为 16 MiB。

这是分析时的磁盘缓存快照，不是整段运行全部图片的分布，也不是应用内存账单。JPEG 解码器可能支持直接缩放，不能把原图像素估算当成确认发生的完整解码分配。

代码确认：此前每次下载均使用会增长的 `MemoryStream`，随后 `ToArray()` 再复制一份；压缩原图可能进入 LOH，即使最终只缓存小头像像素，下载和解码阶段仍有临时开销。Windows 解码器、GDI、网络、WinUI 与分配器的原生占用未被现有计数完整覆盖，因此不能解释成“315 MiB 全是头像”或承诺一次改动全部消除。

## 本批改动

1. CDN 响应提供合法 `Content-Length` 时，直接分配最终原图数组并准确读入，去掉该路径的 `MemoryStream` 扩容和 `ToArray()` 复制。校验短读、超长响应，保留 2 MiB 下载上限、取消、超时、白名单、重定向限制及两路下载。
2. 无长度响应沿用有界读取；仅将 16 KiB 传输缓冲借用自共享数组池，成功、失败和取消均归还。缓存像素及交给解码器的最终原图不进入数组池，避免回收后仍被消费者访问。
3. 诊断 schema 4 新增私有工作集、GC 已提交量、最近 GC 后的分代大小／碎片和待终结对象数。私有工作集使用与压力观察相同的 Windows EX2 接口，不支持时留空，不替换成其他指标。
4. 新增成功网络／磁盘读取字节、单张原图压缩正文峰值，以及有长度／无长度成功读取次数。累加字节反映周转压力，不代表常驻内存；未记录失败或取消请求已经读取的部分流量。
5. 分析脚本兼容旧日志，新增字段缺失时返回 null。保持默认关闭、五秒采样、四个 2 MiB 滚动文件和数字化日志。

图片下载内容、解码档位、显示质量、字体、阴影、帧率、消息容量、历史、登录及停止／换房语义保持原状。不强制 GC、不裁剪工作集、不手动释放 COM，不清理用户真实缓存或历史。
