# 性能诊断与首批分配优化

## 如何采集

1. 打开本版，在左侧进入 **性能诊断**，点击 **开始记录**。默认关闭，重启后也关闭。切换页面或隐藏主窗口后继续记录。
2. 先选择“空闲 / 无弹幕”，保持常用浮窗布局记录约 2 分钟。
3. 切换为“正常监视”，使用真实直播记录 3–5 分钟。有大量消息时选择“大量弹幕”，保持原有字号、显示模式及显示器设置，便于比较。
4. 可分别记录隐藏主窗口、隐藏浮窗、浏览历史、调整浮窗等场景。没有必要为了采样打开所有功能。
5. 出现增长或卡顿后继续保留几分钟，再点击 **停止记录 → 打开日志目录**。将目录下 `performance.0.jsonl` 到 `performance.3.jsonl` 一起提供，供下一轮分析。

目录：`%LOCALAPPDATA%/BilibiliLiveAssistant/diagnostics`。

每 5 秒一个 JSONL 样本；最多四个文件，每个不超过 2 MiB。最新文件为 `performance.0.jsonl`，开启新会话或文件写满会滚动保留旧文件。文件写入错误只在诊断页显示错误类型，监视继续。退出最多等待诊断任务 2 秒；异常退出可能缺少最后一个采样区间或最后一行。

若同时打开多个软件副本，只有取得当前日志文件写权限的一份能够记录；另一份诊断页显示文件异常，不影响直播监视。

## 记录内容和边界

- CPU：本进程 CPU 时间增量 / 实际采样秒数 / .NET 可用逻辑处理器数 × 100。记录归一化口径和构建版本，不包含 BrowserHost、浏览器或系统 DWM 进程；与任务管理器瞬时值可能不同。
- 内存：进程工作集、私有提交、托管存活量估计、最近一次 GC 的堆大小和碎片量、分配增量及分代回收次数。`GC.GetTotalMemory(false)` 不强制回收；GC 堆观测值在未发生 GC 时可能保持不变。
- 线程、进程句柄、GDI / USER 对象，便于观察资源数量是否持续增长。
- UI：低优先级调度延迟、快照年龄、当前页面和可见状态。始终至多一个待执行 UI 脉冲；阻塞期间继续采集进程资源，UI 快照标为旧数据，区间耗时不重复记录。正常快照年龄通常接近 5 秒。
- 渲染：批处理、共享帧回调、消息位图生成、五类区域绘制的区间次数、总耗时和单次最大耗时；回调最大间隔及超过目标周期 1.5 倍的次数。它们是墙钟耗时，嵌套项会重叠，不能相加当作 CPU；回调间隔也不等于屏幕实际呈现帧率。
- 资源：各浮窗内容数量、待播数量、当前模式、尺寸、字号、阴影、估计位图字节数，原生画布数量和字节数，图片缓存命中 / 请求 / 淘汰 / 失败数及预算估计，媒体待请求数量，历史实时待写数量 / 字节、累计批次耗时和遗漏数。计数不扫描磁盘或图片内容，缓存与位图估计不代表完整进程内存。

日志不记录房间号、UID、昵称、正文、图片地址、Cookie、登录令牌或配置全文。不新增网络请求，不检查用户历史数据库。关闭后不运行诊断采样计时器；少量缓存 / 画布 / 历史批次计数随原有操作更新。

## 分析工具

在仓库中用 PowerShell 7 运行：

```powershell
./scripts/analyze-performance.ps1 -OutputPath ./artifacts/performance-report.json
```

也可用 `-LogDirectory` 指向另存的日志目录，用 `-Session` 指定会话；默认分析保留日志中的最新会话。工具只读上述四个日志文件，不读取设置或历史库，忽略不完整 JSON 行。按连续场景段输出 CPU P50 / P95 / 最大值、内存峰值与 MiB/分钟回归斜率、分配速率、吞吐、UI 延迟、队列 / 缓存 / 句柄峰值、丢弃增量及区间绘制耗时。

发布目录也附带 `tools/analyze-performance.ps1`，可在该目录使用 PowerShell 7 执行 `./tools/analyze-performance.ps1 -OutputPath ./performance-report.json`。

增长率至少需要 3 个点；短时间缓存预热、GC 时机和原生图形资源都可能造成增长，不能直接认定泄漏。UI 快照可能滞后进程采样，切换场景前后一个区间也可能混有过渡活动。日志轮转后只分析尚保留的区间。

下一轮根据实际日志定位：空闲定时唤醒、单类绘制与位图重建、图片重复请求或缓存抖动、归档积压、托管或原生资源增长。优化前后使用相近消息量、相同显示配置做对照，检查遗漏、可读性与流畅度，不能靠降低功能或显示质量宣布优化成功。

## 首批代码优化

图片 URL 校验复用静态域名及子域后缀表，去除每次校验的白名单数组、匹配闭包及后缀拼接；已符合策略的 HTTPS 默认端口无片段地址直接复用 URI。保留原域名白名单、HTTP 升级 HTTPS、端口清理与片段移除策略。图片入缓存时复用一次帧占用计算，避免同一分配流程重复求和。

这些更改有明确的分配路径依据，但尚未取得用户实际运行日志，未声称 CPU 或内存降低的具体幅度。
