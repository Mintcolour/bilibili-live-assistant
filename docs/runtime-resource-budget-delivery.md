# CPU／内存优化候选版

当前为待验收候选，不宣称已达到160 MiB或启动占用两倍的目标。一小时、本地刷新率和真实使用日志仍需核对；编译成功不等于性能改善。

## 新增进房头像开关

在“可视化设置 → 进房／关注”或“概览消息”关闭“加载进房头像与头像框”，保存应用。互动浮窗的“更多外观”菜单也可切换。默认开启；关闭后进房提示保留名字、粉丝牌和身份，不补全头像或请求图片；关注、礼物、SC和普通弹幕不受此独立开关影响。历史保存原消息实际携带的链接，不额外补取。

## 本轮调整

- 图片解码输入去除整份WinRT中间复制，进行中正文共享；已核对的头像路径请求对应尺寸缩略图，失败有界回退。
- 概览按列同步，复用相同图片租约和文字／徽章控件；浮窗同轮图片通知合并一次重绘。
- 浮窗表情按实际物理尺寸选64／128／256档；大表情、背景及装饰保留所需分辨率。放大设置时补取新的档位。
- 动画只保留当前显示帧和一次下一帧上传，继续保留原动画帧数、帧率及并发限制。
- 分块下载改为有上限的小分段，避免扩容中间大数组；高压力时优先回收无租约显示源、收紧转换并发。没有强制GC或裁剪工作集。
- 大于64 KiB的已知长度图片正文完整读完后才生成连续数组，减少取消时的大数组分配；同批可见行换位可接续原图片请求，下一轮仍无消费者才取消。换房和退出继续立即取消，不增加轮询。
- 字体、阴影、透明度、目标帧率、消息容量、历史库及账号流程保持原规则。停止／停播／同房重新监视保留内容，换房清理旧代资源。

## 当前验证范围

仅进行静态核对、Release x64编译、文件核对及独立StressApp运行。未启动正式软件或BrowserHost，不运行普通功能自动测试，不读取真实设置、Cookie或历史库。

最终v12隔离短测完成60秒、50条／秒共3000条消息，进房头像和动画开启，概览＋浮窗同时显示，随后执行阅读检查和30次隐藏恢复。外部约250ms采样830次，私有工作集峰值137.43 MiB，未观察到绝对160 MiB超限；CPU P95为4.49%，分配速率约10.12 MiB/秒。远程桌面环境返回32 Hz，不能直接与本机60／165 Hz比较。成功可见WinUI绑定P95为178ms，此数值不代表GPU呈现或浮窗延迟。

停止／停播／同房保留、换房清空检查通过；最终隐藏20秒后活跃图片、租约、显示源、待创建任务和上传计数归零。这不代表进程已将全部内存返还系统。该次模拟单次启动约52.56 MiB，仍超过自身两倍约束；没有三次启动或一小时完整验收。前序v11低频运行约6.6分钟即因自身两倍约束失败而提前结束，不能判长期通过。详细证据见`resource-budget-progress.md`及隔离报告。

隔离程序的启动入口与正式软件不同，约50–55 MiB的模拟启动值不能冒充正式软件约80 MiB的基准。报告同时列出自身两倍约束及绝对160 MiB，任何一项超限都如实标明，不重设基准。

## 发布与手动验证

按本轮收尾要求不再启动后续模拟，发布到新目录`artifacts/releases/runtime-resource-budget-v12`供实际使用验证，保留旧候选。仅本机目录继承`runtime-image-buffers`设置并校验字节一致。分享ZIP不含设置、历史库、诊断日志或调试数据。保留ReadyToRun、PerMonitorV2、SQLite、BrowserHost、扩展及性能分析工具。

请人工检查进房头像开关、关注头像、静态／透明表情及动画、宽表情、大表情、调整大小后的补图、100%／150%／200% DPI、媒体封面、拖动布局和换房。真实日志需在默认头像开启、概览＋浮窗同时显示下覆盖至少一小时；同时观察CPU、图片出现延迟和私有工作集峰值，不能只看结束时内存。
