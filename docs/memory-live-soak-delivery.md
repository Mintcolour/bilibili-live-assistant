# 内存优化与一小时观察交付

## 结论

按用户最后确认的“一小时数据稳定即可”收尾。在远程桌面、概览＋浮窗持续显示、每秒 50 条模拟消息的条件下，连续观察超过一小时，私有工作集采样峰值 **150.22 MiB**，低于任务管理器常见“内存”列的 180 MB 目标。没有完成两小时验收，也没有实体屏幕 60／165 FPS 下的长时结论。

| 项目 | 结果 |
| --- | --- |
| 运行 | `stable-rows-two-hour-v2`；名称沿用原计划，实际按一小时观察结束 |
| 最后采样时间／连续流量覆盖下限 | 3,707.77 秒／3,692.76 秒 |
| 输入消息／轮换用户 | 184,885 条／20,000 个 UID |
| 私有工作集：峰值／末值 | 150.22／140.75 MiB |
| 私有提交量：峰值／末值 | 215.76／206.18 MiB；未低于 180 MiB，不与工作集混用 |
| 总工作集：峰值／末值 | 315.88／306.40 MiB；包含共享页，不作为本轮 180 MB 判定值 |
| 第 45–60 分钟工作集斜率 | 约 +0.0392 MiB／分钟 |
| 双窗口可见性／最大采样间隔 | 所有流量采样均可见／约 5.06 秒 |
| 归档观察期间丢失／写入失败 | 0／0 |
| 显示条件 | 远程显示适配器 32 Hz，目标 32 FPS，整段平均约 19.47 次帧回调／秒 |

采样约每 5 秒一次，峰值不覆盖采样间瞬态。回调频率不是 GPU 呈现 FPS。模拟仅替换网络传输、图片 HTTP 和设置存储；使用实际 WinUI 概览、浮窗、图片缓存与 SQLite。图片 URL 轮换，但头像使用 8 种本地固定样本，不代表所有真实格式、全部布局和网络条件。

## 修改与行为

- 概览用稳定行槽位更新记录，普通弹幕、礼物、SC 和普通进房复用控件、文字、徽章、头像与表情，不随每条新消息重建列表容器。
- 仅刷新已实现行；每列回收池最多 16 个，隐藏、清空和样式变化时回收。控件重绑操作按钮与身份，取消旧图片等待，过期结果不进入新消息。
- 明确解除富文本内嵌控件、提示、图片及事件引用；统一复用有数量上限的字体和画刷。
- 保留正在阅读的记录及行内偏移，防止大量消息导致阅读跳动。
- 停止监视、停播、同房重新监视保留内容；换房清原房间内容及缓存。
- 图片磁盘索引改为增量维护，避免反复枚举目录。图片资产仍为 24 MiB 上限，共享显示源闲置仍为 8 MiB／256 项。

字体、DPI、阴影、透明度、请求帧率、消息容量、礼物合并、历史归档与登录流程没有降低或更改。没有强制 GC、工作集裁剪或手动 COM 释放。

分支为 `memory-live-soak`，主要 UI 优化提交为 `65a7c71`。阶段与对照证据见 [进展记录](memory-live-soak-progress.md)。

## 验证边界

正式应用 Release x64 编译通过。隔离压力构建的原生 XAML DLL 与原 SDK `1.7.250401001` 的 NuGet MSIX 哈希一致，运行时实际加载路径和哈希也已核对。

此前完整的 `reading-layout-order-check`（90 秒／4,500 条流量）验证了普通弹幕与 SC 的记录、行内像素偏移不变；停止保留、同房保留、停播保留和换房清理四项断言通过；头像、徽章、透明表情截图检查通过，存档无丢失、无写入失败且队列排空。

一小时观察按用户新要求结束，仅终止了路径核对后的隔离压力进程，没有启动真实 App 或 BrowserHost，没有读取真实 Cookie、设置内容或历史库。该长观察没有执行原来两小时末尾的四项断言和优雅退出排空；最后采样有 45 条待归档，可能未持久化。没有将观察结束写成正常 `completed.json`。不能用它证明本轮全部输入已写入历史，或真实应用退出已经实测。

第一轮在窗口隐藏后不满足连续双窗口条件，已单独标记中断，不与第二轮拼接。原基线首次在约 166 秒／7,796 条消息采到超过 350 MiB 的是私有提交量，不能说是任务管理器工作集达到 350 MB。不同刷新率、SDK 试验和 dump 干扰的数据也不用于直接计算改善百分比。
